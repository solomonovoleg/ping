# Как отдать iOS-сборку тестерам, пока приложения нет в App Store

Есть два рабочих способа: **TestFlight** (удобнее всего) и **Ad Hoc** (если TestFlight по какой-то причине не подходит).

---

## Вариант 1: TestFlight (рекомендуется)

Так тестеры ставят приложение через приложение **TestFlight** от Apple. Приложение в App Store публиковать не нужно — оно просто загружается в App Store Connect для теста.

### Что нужно

- **Apple Developer Program** (платная подписка, ~99 $/год). Без неё TestFlight и Ad Hoc недоступны.
- Аккаунт в [App Store Connect](https://appstoreconnect.apple.com).

### Шаги

1. **Создать приложение в App Store Connect** (если ещё нет)  
   - Войди в App Store Connect → **Мои приложения** → **+** → **Новое приложение**.  
   - Укажи платформу iOS, название, основной язык и т.д. Сохрани. Публиковать в магазин не обязательно.

2. **Собрать веб-бандл и синхронизировать Capacitor (каждая новая версия для тестеров)**  
   - В корне репозитория положи **`deploy.env`** (как на сервере): в бандл попадут `VITE_API_URL` / `VITE_WS_URL` и при необходимости TURN — иначе тестеры увидят не тот бэкенд или звонки могут не работать через NAT.  
   - Команда: **`npm run build:ios:prod`** (это `capacitor:assets` + прод-сборка клиента + `npx cap sync ios`).  
   - Если меняли нативные зависимости: `npm run ios:pod-install`.  
   - Открой проект: **`open ios/App/App.xcworkspace`**.  
   - В Xcode: **General → Build** — увеличь **Build** (`CURRENT_PROJECT_VERSION`), иначе Apple не примет повторную загрузку с тем же номером. Версию для пользователя (**Version** / `MARKETING_VERSION`) меняй при смысловом релизе.  
   - Схема **App**, устройство **Any iOS Device (arm64)** (не симулятор).  
   - Меню **Product → Archive**. Дождись окончания архивации.

3. **Загрузить архив в App Store Connect**  
   - Откроется окно **Organizer** с архивом. Нажми **Distribute App**.  
   - Выбери **App Store Connect** → **Upload**.  
   - Дальше по шагам: подпись (обычно автоматически), загрузка. После загрузки подожди 5–15 минут, пока сборка появится в TestFlight.

4. **Добавить тестеров**  
   - В App Store Connect: твоё приложение → вкладка **TestFlight**.  
   - **Внутренние тестеры**: до 100 человек из твоей команды в App Store Connect (добавляются по ролям).  
   - **Внешние тестеры**: до 10 000. Нужно создать **группу** (например, «Бета-тестеры»), добавить туда email приглашённых. Первая сборка для внешней группы должна пройти быструю проверку Apple (обычно до 24 часов).

5. **Что делает тестер**  
   - Получает на почту приглашение от TestFlight.  
   - Устанавливает приложение **TestFlight** из App Store (если ещё нет).  
   - По ссылке из письма или в TestFlight принимает приглашение и нажимает **Установить** рядом с твоим приложением.

Итог: тестер ставит приложение как обычное, через TestFlight, без кабеля и без регистрации UDID. В App Store приложение при этом может не быть — оно только в TestFlight.

## Вариант 2: Ad Hoc (без TestFlight)

Подходит, если нет возможности использовать TestFlight (например, нет доступа к App Store Connect или нужна раздача «напрямую»). Ограничения: не больше **100 устройств в год** на команду, и на каждом устройстве должен быть зарегистрирован **UDID**.

### Что нужно

- Apple Developer Program.  
- UDID каждого iPhone, на который ставишь сборку.

### Как узнать UDID у тестера

- **Способ 1:** iPhone подключить к Mac → открыть **Finder** (или iTunes на старых macOS) → выбрать iPhone → клик по серийному номеру, пока не покажется UDID.  
- **Способ 2:** тестер заходит на сайт типа [get.udid.io](https://get.udid.io) с iPhone — сайт покажет UDID (осторожно с такими сервисами с точки зрения конфиденциальности).

### Шаги

1. **Зарегистрировать устройства в Apple Developer**  
   - [developer.apple.com](https://developer.apple.com) → **Certificates, Identifiers & Devices** → **Devices** → **+** → ввести UDID и имя устройства.

2. **Создать Ad Hoc provisioning profile**  
   - **Profiles** → **+** → **Ad Hoc** → выбрать App ID приложения → выбрать сертификат распространения → выбрать **все зарегистрированные устройства** → сохранить и скачать профиль (двойной клик для установки в Xcode).

3. **Собрать IPA в Xcode**  
   - В проекте выбрать схему **App**, в настройках схемы (**Edit Scheme…**) для конфигурации **Release** указать твой Ad Hoc профиль.  
   - **Product → Archive** → в Organizer: **Distribute App** → **Ad Hoc** → выбрать профиль → экспорт. Получится папка с `.ipa`.

4. **Передать тестеру**  
   - Отправить ему `.ipa` (например, ссылкой на скачивание) и установочный профиль (если нужен отдельно).  
   - Установка на iPhone: через **Apple Configurator 2** на Mac (телефон подключен кабелем) или через сервисы вроде **Diawi** ([diawi.com](https://www.diawi.com)) — загружаешь IPA, даёшь тестеру ссылку; он открывает её на iPhone в Safari и нажимает «Установить».  
   - После установки тестеру может понадобиться: **Настройки → Основные → VPN и управление устройством** → доверять разработчику.

Минусы: лимит 100 устройств в год, нужно каждый раз собирать UDID и обновлять профиль при добавлении новых людей. Для постоянного тестирования удобнее TestFlight.

---

## Кратко

| Способ      | Нужен Developer Program | Как тестер ставит приложение      | Ограничения                    |
|------------|---------------------------|-----------------------------------|--------------------------------|
| **TestFlight** | Да                       | Приложение TestFlight, приглашение по email | До 10 000 внешних тестеров     |
| **Ad Hoc**     | Да                       | Ссылка на IPA или установка с Mac | До 100 устройств в год, нужен UDID |

Если у тебя уже есть Apple Developer и доступ к App Store Connect — лучше сразу настроить **TestFlight**: один раз загрузил сборку, добавил людей по email, они ставят приложение в пару тапов. Публиковать приложение в App Store при этом не обязательно.

Если что-то из шагов не получается — напиши, на каком шаге застрял и что показывает экран/терминал, разберём по шагам.
