# AI Search — память по диалогам без «скармливания» всей переписки

**Полное описание алгоритма (дебаунс, батч, курсор, hot, кеш, API):** [`docs/AI_SEARCH_ALGORITHM.md`](../../docs/AI_SEARCH_ALGORITHM.md).

## Идея

- После общения в чате **небольшой батч** последних/новых текстовых сообщений уходит в модель **один раз** (дебаунс ~25 с на пользователя).
- Модель возвращает **JSON**: теги тем, коммерческие и поведенческие интересы, плюс **`hot_now`** — явное намерение «купить/выбрать сейчас» (фен, такси и т.д.).
- Долгий профиль: `ai_search_dialogue_tags`, `ai_search_interests`.
- Быстрый таргетинг: **`ai_search_hot_signals`** с `expires_at` (по умолчанию продлевается на 48 ч при новом упоминании) + **кеш в памяти процесса** (~45 с) для `GET /api/ai-search/hot`.
- Поиск (`GET /api/ai-search?q=`) идёт **по индексу** (ILIKE), а не по полному тексту всех сообщений.

## Отключение

- Нет `OPENROUTER_API_KEY` — индексация не вызывается.
- `AI_SEARCH_ENABLED=0` — явно выключить индексацию (поиск по уже сохранённому остаётся).

## Переменные окружения

- `AI_SEARCH_HOT_TTL_HOURS` — на сколько часов продлевать «горячий» сигнал при повторном упоминании (1–168, по умолчанию 48).
- `AI_SEARCH_HOT_L1_MS` — TTL in-memory кеша списка hot для пользователя (мс, 5000–300000, по умолчанию 45000).

## API

- `GET /api/ai-search?q=текст&limit=20` — теги и интересы пользователя.
- `GET /api/ai-search/hot?limit=16` — только активные горячие сигналы (быстро, с L1-кешем).
- `GET /api/ai-search/ad-context?limitHot=12&limitCommercial=15&limitBehavioral=15` — hot + топ commercial + топ behavioral.
- `POST /api/ai-search/ingest-chat` body `{ "chatId": "..." }` — ручной прогон для чата.

## Хук

`server/messages/service.ts` после текстового сообщения вызывает `scheduleAiSearchIngest`.
