# EDGE — продуктовая спецификация (микросервис)

Документ фиксирует видение: **EDGE** — отдельный тип единицы контента на **борде создателя** (как фото/видео), но **интерактивный**. Сейчас в приоритете **персонаж (тамагочи)**; остальные типы закладываем в модель данных и API **расширяемо**.

Связь с платформой уже есть: пост хранит **`edge_id`** → клиент открывает Companion / интерактив. Платформа **не** дублирует игровую логику — только пост, лента, чат, подписки, посты/комменты (для глобальных заданий).

---

## 1. Сущности (обязательные поля)

| Поле | Описание |
|------|----------|
| **EDGE ID** | Стабильный публичный идентификатор кампании/юнита (уже `posts.edge_id` / UUID). |
| **Тип EDGE** | `character` \| `roulette` \| `catalog` \| `quiz` \| `quest` \| `challenge` \| … (расширяемый enum + JSON-конфиг под тип). |
| **Создатель** | `platform_user_id` создателя (без FK в БД EDGE — opaque id от платформы). |
| **Участники** | Связь «пользователь ↔ EDGE» + роль при необходимости (игрок, модератор и т.д.). |

---

## 2. Типы контента EDGE (дорожная карта)

| Тип | Суть | Статус |
|-----|------|--------|
| **character** | Тамагочи: уровень, состояния, кормление, задания, лидерборд | **MVP** |
| **roulette** / мини-игры | Быстрое действие, спиннер | Позже, общий слот `surface` + правила |
| **catalog** | Товары, корзина, промокоды | Позже |
| **quiz** | Квиз | Позже |
| **quest** | Квестовая цепочка | Позже |
| **challenge** | Челленджи | Позже |

**Принцип расширяемости:** таблица `edges` (или `campaigns`) с полями `type`, `config_json` (схема зависит от `type`); для персонажа — вложенная структура имя/картинка/призы/правила; для рулетки — другая.

---

## 3. Настройки создателя (персонаж / кампания)

- **Название** (имя персонажа / кампании).
- **PNG персонажа** (на белом фоне) — URL в объектном хранилище **платформы** или EDGE; в EDGE храним только `asset_url` + метаданные.
- **Призы** — сущность «приз»: текст, опционально картинка, опционально видео (для выдачи в ЛС).
- **Правила выдачи призов** (максимально гибко, хранить как **декларативный конфиг**), примеры:
  - случайный среди всех участников;
  - случайный среди топ-10 лидерборда;
  - топ-1 на фиксированную дату;
  - три места среди топ-5 на дату;
  - комбинации (несколько правил / несколько призовых пулов).
- **Режим выдачи:** автоматически / вручную (модерация создателя или админа).
- **Итоги:** дата подведения итогов; после неё — расчёт победителей и отправка наград.

Выдача в **ЛС чата** — вызов **API платформы** (сервер-сервер, секрет): «отправить пользователю X сообщение с текстом/медиа». EDGE не хранит историю чата, только факт «выдано / ожидает ручного подтверждения».

---

## 4. Игрок и персонаж

- Каждый **игрок** видит **своего** экземпляра «живого» персонажа в рамках **одной** EDGE-кампании того же **создателя** (один shared asset/лор, разный **state** на пользователя).
- **Уровень** — число + опыт / правила роста.
- **Состояния** — конечный набор или строка + приоритет: спит, туалет, веселье, грусть, плач, «нужна помощь» и т.д.; правила переходов от времени и действий (корм, тапы, пропуски).
- **Настроение / метрика заботы** — растёт при активности, падает при пропусках (например не покормили вовремя).

В БД EDGE: таблица вроде **`edge_participants`** + **`character_states`** (или одна строка state JSON на пару `edge_id + platform_user_id`).

## 5. Задания (три класса)

### 5.1 С персонажем

Примеры: кормить 3 дня подряд; настроение ≥ 50 три дня; ≥ 20 тапов в день.  
Проверка **полностью в EDGE** по событиям и таймерам.

### 5.2 Глобальные (платформа)

Примеры: подписаться на создателя; пригласить 3 человек; написать пост; 3 комментария; 7 дней захода подряд.

**Интеграция:** EDGE не видит БД платформы. Варианты (выбрать при реализации):

- **A)** Платформа шлёт **webhook** в EDGE (`POST /v1/hooks/platform`) при событиях (follow, post, comment, streak).
- **B)** EDGE периодически запрашивает **внутренний API платформы** «статус задания Z для user U» (только server-to-server + секрет).
- **C)** Гибрид: часть событий push, часть pull.

В спеке закладываем таблицу **`tasks`** с полем `scope: character | global | commercial` и `platform_task_key` для маппинга.

### 5.3 Коммерческие

Примеры: номер телефона в списке заказов магазина; фото-отзыв на модерацию.

- Списки телефонов / файлы — хранение и сравнение на EDGE или импорт хэшей; **PII** — минимизировать (хэш нормализованного номера).
- «Скрин + админ подтвердил» — статус задания `pending_review` → API админки платформы или EDGE-admin.

---

## 6. Баллы и лидерборд

- За выполнение заданий начисляются **баллы** (+); за провалы / дедлайны — штрафы (−), если задано правилами.
- **Лидерборд** по `edge_id` + окно времени; у окна **дедлайн сброса** (сезон / тур).
- История сезонов — опционально таблица **`leaderboard_periods`** для архива и прошлых победителей.

**Целевая модель (два рейтинга, призы, заморозка):** см. **`docs/EDGE_LEADERBOARDS_AND_PRIZES_SPEC.md`** — основной vs дополнительный рейтинг, независимые баллы, включение в настройках, вторая страница в Companion при двух включённых, привязка приза к рейтингу, момент выдачи и **ручной сброс заморозки** создателем.

---

## 7. Награждение

- Автоматически или вручную (флаг на правило / на кампанию).
- Гибкие сценарии: топ-3, случайно среди взаимодействовавших с ненулевым рейтингом, и т.д. — в **`prize_rule`** JSON (DSL или предопределённые шаблоны + параметры).
- Контент награды: текст / текст+картинка / текст+видео → отправка в ЛС через платформу.

## 8. Отображение в продукте

- **Публикация:** любая EDGE-кампания создателя выходит в **ленту подписчиков как обычный пост** у платформы: строка в `posts` с заполненным **`edge_id`** (= `public_id` кампании в БД EDGE). Текст/медиа поста — как у любого поста; поверх — интерактивный блок.
- **Лента:** в теле поста ренерится **встраиваемая карточка** (`EdgeCompanionFeedCard`, по умолчанию `variant="feed"`) — тапы/прогресс прямо в ленте; полный экран: **`/edge/{edgeId}?back=…`** (короткий путь; `back` — только доверенные внутренние URL). Редирект со старого **`/edge/companion?edgeId=…`** сохраняет закладки. Вариант **`banner`** — компактная вставка **без** анимации входа карточки во вьюпорт.
- **Полноэкранный макет «Персонаж»** совпадает с лентой: призы · персонаж · метрики; ниже — действия ухода и пресеты заданий (`EdgeParticipantPetCard` / `CharacterSurfacePanel`).
- **Полировка только UI (не игровая логика):** `client/src/features/edge-companion/feed-delight/` — разовый entrance карточки в ленте, подсказка свайпа, акцент CTA для гостя/новичка, лёгкая аура персонажа в ленте; описание границ — `feed-delight/ARCHITECTURE.md`.
- **Полный экран Companion:** отдельная страница с **«Назад»** на источник: из ленты → `/posts`, со страницы поста в профиле → **`/profile/:id/post/:postId`** (параметр `back` валидируется, только внутренние пути).
- **Свайп-разделы (Embla):** горизонтальный пейджер — по умолчанию старт на **«Персонаж»**; остальные экраны: **О кампании** (мини-статья из JSON), **Лидерборд** (если включён флаг кампании), **Итоги** (текст/победители из JSON), **Призы** (шаблоны из `gifts_json`). Порядок задаётся в **`edge_campaigns.config_json.companion.surfaceOrder`**. При смене слайда — лёгкий **хаптик без звука** (`triggerTapFeedback`), чтобы не перегружать ленту и полный экран. Под индикатором точек — строка **«Свайп — ещё: …»** (общая для ленты и Companion, `feed-delight/build-swipe-hint.ts`). Точки-вкладки — тап без лишнего шума.
- **Социальный слой платформы** для такого поста **тот же**, что и для обычного: **просмотры**, **реакции**, **комментарии**, **шаринг в чат** / репост — всё идёт по `post.id`; сервер при необходимости дополнительно шлёт события в EDGE (XP за view/react/share и т.д. по `posts.edge_id`).
- В **борде создателя** (позже): карточка типа «EDGE» с превью (иконка типа + название + CTA).

Клиент выбирает набор экранов по **`edgeType`** и флагам; контент статей/итогов — из **`GET /v1/companion/campaign-config`** (`companionUi` в JSON).

Редактирование **`config_json.companion`** в админке приложения: **`/admin/edge-companion`** → `POST /api/admin/edge/companion-config` → EDGE **`POST /v1/campaign/companion-config`** (секрет).

### Пример `config_json.companion`

```json
{
  "companion": {
    "surfaceOrder": ["character", "info", "leaderboard", "results", "prizes"],
    "infoArticle": {
      "title": "О птенце",
      "blocks": [
        { "type": "paragraph", "text": "Текст для участников." },
        { "type": "image", "url": "https://...", "alt": "Обложка" },
        { "type": "video", "url": "https://..." }
      ]
    },
    "results": {
      "lastDrawSummary": "10 марта выбрано 3 победителя",
      "nextDrawHint": "Следующий розыгрыш — 1 апреля",
      "winners": [{ "title": "Главный приз", "name": "Анна К." }]
    }
  }
}
```

## 9. Изоляция микросервиса (напоминание)

- Отдельный процесс, отдельная БД/схема, таймауты и fallback на платформе для `/api/edge/*`.
- Сбой EDGE не ломает чаты и ленту без EDGE-блока.
