# UIX Specialist Guide: библиотеки, кайф, детали

**Для кого:** когда нужен не «про токены и отступы», а про **ощущение** интерфейса — полировка, микро-взаимодействия, современные практики и библиотеки, которые используют топовые дизайнеры и продукты.

---

## 1. Современные UIX-библиотеки (что реально ставить и юзать)

### У вас уже есть

| Библиотека | Зачем | Как использовать по полной |
|------------|--------|-----------------------------|
| **Framer Motion** (у вас `framer-motion@12`) | Анимации, жесты, spring-физика | Сейчас почти не используется в клиенте. Подключить `motion` (или `framer-motion`) и добавить: `whileTap`/`whileHover` на кнопки, `AnimatePresence` для модалок/экранов, stagger для списков чатов/постов. |
| **Radix UI** | Доступность, семантика, примитивы | Уже ок. Документация Radix + Motion: [Animating Radix with Motion](https://motion.dev/docs/radix) — для Dialog/Sheet делать enter/exit через `AnimatePresence` и `motion.div`. |
| **Tailwind + tw-animate-css** | Быстрые классы анимаций | Используйте `animate-in`, `fade-in`, `slide-in-from-bottom-2` последовательно; длительности держать 200–300ms. |
| **Capacitor Haptics** | Тактильная отдача на тап | Уже есть `triggerLightHaptic` в Login — распространить на ключевые действия: отправка сообщения, лайк, переключение табов, важные кнопки. |

### Что добавить для «кайфа» и полировки

| Библиотека / ресурс | Что даёт | Рекомендация |
|---------------------|----------|--------------|
| **Motion for React** (новое имя Framer Motion) | Официальный гайд по жестам, spring, `useReducedMotion` | Документация: [motion.dev](https://motion.dev). Перейти на `motion/react` при апгрейде или продолжать использовать `framer-motion` — API совместим. Главное — начать использовать: `whileTap`, `whileHover`, `AnimatePresence`, stagger. |
| **SmoothUI** | 50+ готовых анимированных компонентов под shadcn/ui (кнопки, карточки, инпуты, текст-эффекты) | [smoothui.dev](https://www.smoothui.dev) — ставить выборочно через их CLI (как shadcn). Имеет смысл для: кнопок с магнитным эффектом, карточек с hover, shimmer-скелетонов. |
| **AnimateX** (если нужны готовые блоки) | Готовые анимированные кнопки/карточки на Framer Motion + Tailwind | [animatex.newtonraul.me](https://animatex.newtonraul.me) — copy-paste компоненты. Можно взять 2–3 паттерна (например кнопка с shimmer или нажатием) и встроить в свою дизайн-систему. |
| **Sonner / Radix Toast** | Тосты с анимацией появления/исчезновения | У вас уже тосты; убедиться, что появление — не резкое (fade + лёгкий slide), длительность ~250ms. |

Итого по библиотекам: **не обязательно ставить всё подряд**. Достаточно: (1) активно использовать **Framer Motion** в клиенте, (2) при желании взять 1–2 компонента из **SmoothUI** или **AnimateX** как референс, (3) везде, где уместно, добавить **хаптик**.

## 2. Практики «кайфа» и юзабилити (по опыту дизайнеров и исследований)

### 2.1 Микро-взаимодействия (micro-interactions)

- **Одна цель на действие** — каждое маленькое движение должно что-то сообщать: «нажал», «загрузилось», «ошибка».
- **Быстрый отклик** — 100–200 ms для hover/tap, 200–300 ms для появления/исчезновения блоков. Не больше 300–400 ms для перехода между экранами.
- **Только transform и opacity** — не анимировать `width`/`height`/margin в горячих путях; так остаётся 60 fps и нет джиттера.

Конкретно по экранам:

| Место | Что добавить |
|-------|----------------|
| Кнопки (отправка, «Войти», «Опубликовать») | `whileTap={{ scale: 0.97 }}` + хаптик на тап. |
| Строки списка (чат, пост) | Лёгкий `active:scale-[0.99]` или через Motion `whileTap={{ scale: 0.99 }}`. |
| Переключатель Вход/Регистрация (Login) | Уже есть переход; можно добавить лёгкий spring при смене (duration 0.2, bounce 0.1). |
| Модалки (комменты, создание поста) | Вход снизу (как сейчас), выход — вниз + fade; через `AnimatePresence` + `motion.div` с `exit`. |
| Нижний навбар | Иконки при тапе — лёгкий scale 0.9 на 100ms. |

### 2.2 Обратная связь (feedback)

- **Мгновенная визуальная реакция** — кнопка должна «прожиматься» в момент тапа, не после ответа сервера.
- **Оптимистичные обновления** — сообщение в чате сразу в списке; лайк на посте сразу перекрашивается. Ошибку показывать тостом, не блокируя UI.
- **Состояния загрузки** — не только спиннер: скелетоны списка (как в Chats) везде, где список (лента, контакты). При желании — shimmer на скелетоне (один общий компонент).

### 2.3 Скелетоны и «ощущение скорости»

- **Скелетон вместо спиннера** для списков — уже есть в Chats; тот же паттерн — в ленте постов, в контактах.
- **Один стиль скелетона** — одна анимация (pulse или shimmer), одни отступы/радиусы. У вас уже есть `Skeleton` в `components/ui/skeleton.tsx` — использовать везде и при желании добавить shimmer (градиент + `animation: shimmer`).

### 2.4 Хаптик

- Уже есть в Login на фокус/ввод. Добавить лёгкий хаптик на: отправку сообщения, переключение таба в нижнем баре, лайк/реакция, «Опубликовать», критичные кнопки в настройках.
- Не вызывать хаптик на каждый скролл или движение — только на явное действие пользователя.

### 2.5 Пустые состояния и ошибки

- **Пустое состояние** — одна схема: иконка/иллюстрация + короткий текст + один CTA. Один компонент `EmptyState` и использовать в «Нет чатов», «Нет постов», «Нет контактов».
- **Ошибка** — один вид: иконка (например AlertCircle) + текст + при необходимости кнопка «Повторить». Один набор классов или маленький компонент `ErrorBanner`.

## 3. Длительности и easing (как у профессионалов)

По [SmoothUI Animation Best Practices](https://www.smoothui.dev/docs/guides/animation-best-practices) и вашим константам в `lib/motion.ts`:

| Тип | Длительность | Где использовать |
|-----|--------------|-------------------|
| Микро (hover, tap) | 100–200 ms | Кнопки, иконки, строки списка |
| Стандарт (появление блока) | 200–300 ms | Модалки, тосты, смена экрана |
| Акцент (редко) | 300–400 ms | «Магические» эффекты (например рассыпание) |

Easing:

- **ease-out** для появления: `cubic-bezier(0.23, 1, 0.32, 1)`.
- **Spring** для кнопок и интерактива: `type: "spring", duration: 0.25, bounce: 0.1` (в Framer Motion).

У вас уже заданы `DURATION_FAST_MS`, `DURATION_NORMAL_MS`, `EASING_OUT` — использовать их везде вместо магических чисел.

## 4. Конкретный план внедрения (приоритеты)

### Фаза 1: «Быстрый кайф» (1–2 дня)

1. **Framer Motion на кнопки и списки**
   - Обернуть основные кнопки (Отправить, Войти, Опубликовать, пункты навбара) в `motion.button` с `whileTap={{ scale: 0.97 }}` и `transition={{ duration: 0.15 }}`.
   - В списке чатов и постов — `whileTap={{ scale: 0.99 }}` на строку (или оставить только `active:scale-[0.98]` в Tailwind).
2. **Хаптик**
   - Вызов `triggerLightHaptic()` при отправке сообщения, при тапе на таб в нижнем баре, при «Опубликовать», при лайке/реакции.
3. **Модалки**
   - Комменты, создание поста: выход (exit) через Framer Motion `AnimatePresence` + `motion.div` с `exit={{ opacity: 0, y: 20 }}` и длительностью 200–250 ms.

### Фаза 2: Единый стиль состояний (1 день)

4. **Компонент EmptyState**
   - Иконка + заголовок + описание + опционально одна кнопка. Подключить в Chats, Posts, контакты.
5. **Единый вид ошибки**
   - Один блок (или классы): иконка + текст + при необходимости «Повторить». Использовать на Login, в формах, в модалках.
6. **Скелетоны везде**
   - Лента постов и контакты — те же скелетоны, что в Chats (или один общий список-скелетон). При желании — один shimmer для `Skeleton`.

### Фаза 3: Полировка (по желанию)

7. **SmoothUI или AnimateX**
   - Установить 1–2 компонента (например кнопка с эффектом нажатия или карточка с hover) и встроить в одну-две ключевые точки (главная кнопка на Login или кнопка «Опубликовать»).
8. **Stagger при появлении списков**
   - При первой загрузке чатов/ленты — появление строк с задержкой 30–50 ms друг за другом (`staggerChildren` в Framer Motion).
9. **Проверка reduced motion**
   - Убедиться, что все новые анимации проверяют `usePrefersReducedMotion()` и при `true` дают только fade или без анимации.

## 5. Полезные ссылки (знания интерфейс-дизайнеров и гайды)

- **Motion (Framer Motion):** [motion.dev](https://motion.dev) — жесты, spring, Radix, accessibility.
- **SmoothUI:** [smoothui.dev](https://www.smoothui.dev) — анимированные компоненты под shadcn, best practices по длительностям и easing.
- **Radix + Motion:** [motion.dev/docs/radix](https://motion.dev/docs/radix) — как анимировать Dialog, Sheet и т.д.
- **Микро-взаимодействия (IxDF):** [The Role of Micro-interactions in Modern UX](https://www.interaction-design.org/literature/article/micro-interactions-ux) — зачем нужны и как не переборщить.
- **Исследования:** анимации и скелетоны повышают вовлечённость и воспринимаемую скорость; длительности 200–300 ms воспринимаются как отзывчивые.

## 6. Краткий чек-лист «интерфейс не бред»

- [ ] Все основные кнопки дают визуальный отклик на тап (scale или цвет) в течение &lt; 150 ms.
- [ ] Критичные действия (отправка, публикация, лайк) дают лёгкий хаптик (где поддерживается).
- [ ] Модалки и оверлеи появляются и исчезают с анимацией (не режутся).
- [ ] Списки при загрузке показывают скелетон, а не только спиннер.
- [ ] Пустые состояния везде в одном стиле: иконка + текст + один CTA.
- [ ] Ошибки везде в одном виде (блок или тост с иконкой и текстом).
- [ ] Нет анимаций дольше 300–400 ms в интерактивных сценариях (кроме редких «вау»-моментов).
- [ ] Учтён `prefers-reduced-motion`: при включении — минимум движения или только fade.

Если хочешь, следующий шаг — взять одну фазу (например «Фаза 1») и расписать правки по файлам и строкам кода (например только Chats + Login + одна модалка).
