# Как подключить другого человека к папке проекта на сервере

Есть два варианта: быстрый (через общий доступ) и рекомендуемый (отдельный пользователь на сервере).

---

## Вариант 1: Быстрый — дать коллеге данные для деплоя

Коллега сможет деплоить из своего клона репозитория, используя твой доступ к серверу.

**Что передать (безопасно, например через 1Password / Bitwarden / защищённый канал):**

1. **Копию файла `deploy.env`** из корня проекта (или его содержимое).
   - В нём уже есть: `VPS_HOST`, `VPS_USER`, `VPS_PASSWORD`, `VPS_PATH` (если менял), `DATABASE_URL`, `SESSION_SECRET` и др.
   - Файл **не коммитится** в git — передаётся отдельно.

2. **Инструкцию коллеге:**
   - Клонировать репозиторий: `git clone <url> && cd "PING MOOT"`
   - Положить присланный `deploy.env` в корень проекта (рядом с `package.json`).
   - Установить зависимости и задеплоить: `npm ci --legacy-peer-deps && npm run deploy`
   - Для миграций без полного деплоя: `bash scripts/migrate-on-server.sh` (тоже использует `deploy.env`).

**Минус:** у коллеги будет полный доступ под твоим пользователем (часто `root`) и ко всем секретам в `deploy.env`. Подходит для доверенного человека и быстрого старта.

---

## Вариант 2: Рекомендуемый — отдельный пользователь на сервере

Создаёшь на VPS нового пользователя с доступом **только к папке проекта**. Коллега заходит по своему SSH-ключу, без пароля root.

### Шаг 1: Зайти на сервер под текущим пользователем (root или твой)

```bash
ssh root@130.49.150.92
# или: ssh VPS_USER@VPS_HOST (данные из твоего deploy.env)
```

### Шаг 2: Создать пользователя и папку для ключа

```bash
# Имя пользователя — например имя коллеги или deploy2
sudo adduser colleague   # при необходимости задай пароль (можно пропустить, если вход только по ключу)

sudo mkdir -p /home/colleague/.ssh
sudo chmod 700 /home/colleague/.ssh
```

### Шаг 3: Добавить SSH-ключ коллеги

Коллега присылает тебе **публичный** ключ (файл `~/.ssh/id_rsa.pub` или `~/.ssh/id_ed25519.pub` — содержимое одной строки).

На сервере:

```bash
echo "вставь_сюда_содержимое_id_rsa.pub_или_id_ed25519.pub" | sudo tee /home/colleague/.ssh/authorized_keys
sudo chmod 600 /home/colleague/.ssh/authorized_keys
sudo chown -R colleague:colleague /home/colleague/.ssh
```

### Шаг 4: Дать пользователю доступ к папке проекта

Папка проекта по умолчанию: `/var/www/ping-moot`. Нужно, чтобы пользователь `colleague` мог её читать и писать (для деплоя через rsync).

**Способ A — добавить в группу владельца папки:**

```bash
# Узнать владельца папки (часто root или www-data)
ls -la /var/www/ping-moot

# Если владелец root, создаём группу и даём ей права на папку
sudo chgrp -R colleague /var/www/ping-moot
sudo chmod -R g+rX,g+w /var/www/ping-moot
# Или если папка уже принадлежит группе (например www-data):
sudo usermod -aG www-data colleague
# и тогда права на папку: sudo chmod -R g+rX,g+w /var/www/ping-moot && sudo chgrp -R www-data /var/www/ping-moot
```

**Способ B — сделать пользователя владельцем папки** (если это только этот проект и так удобнее):

```bash
sudo chown -R colleague:colleague /var/www/ping-moot
```

Важно: приложение (PM2) часто запущено от root или другого пользователя. Если сменишь владельца на `colleague`, проверь, что PM2 по-прежнему может читать файлы (например, запуск от того же пользователя или настройка PM2 под `colleague`). Обычно проще оставить владельца как есть и использовать **способ A** с группой.

### Шаг 5: Проверка входа

Коллега с своей машины:

```bash
ssh colleague@130.49.150.92
```

Должен войти без пароля (по ключу). Дальше:

```bash
ls -la /var/www/ping-moot
```

Если видит файлы проекта — доступ к папке есть.

### Шаг 6: Что дать коллеге для деплоя

Передать коллеге **отдельный** `deploy.env`, где:

- **VPS_HOST** — тот же (например `130.49.150.92`)
- **VPS_USER** — `colleague` (новый пользователь)
- **VPS_PASSWORD** — оставить **пустым** (вход по ключу)
- **VPS_PATH** — `/var/www/ping-moot` (если не менялся)
- **DATABASE_URL**, **SESSION_SECRET**, **PORT** и остальное — как у тебя (из твоего `deploy.env`), чтобы приложение не сломалось при деплое.

В `deploy.env` не должно быть пароля root — только секреты приложения (DATABASE_URL, SESSION_SECRET и т.д.). Тогда коллега не имеет доступа к твоему SSH, но может деплоить в общую папку.

---

## Краткая шпаргалка для коллеги

- Клонировать репозиторий, положить в корень присланный **deploy.env**.
- **Деплой:** `npm run deploy`
- **Только миграции на сервере:** `bash scripts/migrate-on-server.sh`
- Папка на сервере: **`/var/www/ping-moot`** (или значение `VPS_PATH` из `deploy.env`).
- Подключиться по SSH: `ssh VPS_USER@VPS_HOST` (подставить из своего `deploy.env`).
