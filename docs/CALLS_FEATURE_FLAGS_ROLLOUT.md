# Calls Feature Flags Rollout

Документ задает безопасный порядок включения новых модулей звонков и обязательные проверки перед каждым шагом.

## Feature Flags

- `VITE_CALLS_FEATURE_NETWORK_QUALITY`
- `VITE_CALLS_FEATURE_CAMERA_FLIP`
- `VITE_CALLS_FEATURE_SCREEN_SHARE`
- `VITE_CALLS_FEATURE_LOCAL_RECORDING`
- `VITE_CALLS_FEATURE_REACTIONS`
- `VITE_CALLS_FEATURE_CAPTIONS_RELAY`

По умолчанию все флаги выключены. Включаем строго по этапам ниже.

## Принципы rollout

- В каждый момент включается только один новый рискованный модуль.
- Если smoke/manual чек не пройден, откатываем только соответствующий флаг.
- Базовый call flow (`accept/reject/hangup/mute`) должен оставаться рабочим на всех этапах.
- Unknown/unsupported API не должен ронять звонок: только graceful fallback + статус.

## Порядок включения

1. `network-quality`
2. `camera-flip`
3. `screen-share`
4. `local-recording`
5. `reactions`
6. `captions-relay`

## Матрица по окружениям

### DEV

Цель: функциональная валидация и негативные сценарии.

- Включаем флаг одного этапа.
- Прогоняем обязательные тесты этапа (см. ниже).
- Если этап пройден 2 раза подряд на разных устройствах/браузерах, переходим к следующему.

Рекомендуемые пары устройств:
- Chrome desktop + Safari iOS
- Chrome Android + Safari iOS

### STAGE

Цель: регресс и межбраузерная стабильность.

- Включаем только те флаги, что прошли DEV.
- Прогоняем полный smoke и этапные тесты.
- Дополнительно: тест с деградацией сети (throttling) и перезаходом в звонок.

Требование для промоушена:
- 0 критичных багов (невозможность начать/принять/завершить звонок).
- 0 блокеров UI (невидимые/неработающие базовые кнопки).

### PROD

Цель: поэтапный релиз без влияния на базовые звонки.

- Включаем по одному флагу в релиз.
- Между релизами минимум 24 часа наблюдения.
- При инциденте откатываем только проблемный флаг.

## Обязательный smoke (каждый этап, все окружения)

1. Аудиозвонок: start -> accept -> talk -> hangup.
2. Видеозвонок: start -> accept -> local/remote video visible -> hangup.
3. Reject входящего: у инициатора корректный статус.
4. Busy case: второй входящий получает busy.
5. Отключение/восстановление сети: звонок не падает с необработанной ошибкой.
6. При всех отключенных флагах поведение звонка совпадает с baseline.

## Этапные проверки

### 1) Network Quality

- При хорошем канале индикатор показывает `good` или `medium`.
- При throttling/потерях пакетoв уровень деградирует до `poor`.
- При завершении звонка индикатор сбрасывается.

### 2) Camera Flip

- На видео-звонке переключение front/back меняет источник без разрыва звонка.
- На unsupported устройствах кнопка не показывается.
- Повторное переключение возвращает предыдущую камеру.

### 3) Screen Share

- Старт шаринга подменяет локальный видео-трек у собеседника.
- Стоп шаринга возвращает камеру.
- Отмена системного диалога шаринга не роняет звонок.

### 4) Local Recording

- Старт записи меняет состояние на `recording`.
- Стоп записи сохраняет локальный файл.
- Ошибка записи не ломает соединение и базовые кнопки.

### 5) Reactions

- Отправка реакции отображается локально и у собеседника.
- Частые клики не приводят к зависанию UI.
- После завершения звонка очередь реакций очищается.

### 6) Video Enhancement

- Toggle переводит режим `off <-> smooth`.
- Если constraints не поддержаны, режим корректно откатывается в `off`.
- Видео и соединение не разрываются.

### 7) Captions Relay

- Включение титров запускает локальное распознавание.
- Текст отправляется собеседнику событием `call.caption`.
- Выключение титров останавливает распознавание.
- Ошибки Speech API не ломают звонок (только статус/сообщение).

## Rollback protocol

Если провален любой этап:

1. Выключить только проблемный флаг.
2. Перепроверить базовый smoke (6 пунктов).
3. Зафиксировать причину в issue: окружение, шаги, ожидание/факт, логи.
4. Повторный rollout только после фикса и повторного прогона на DEV -> STAGE.

## Минимальный checklist перед включением флага в PROD

- Этап прошел DEV на 2 браузерах и 2 устройствах.
- Этап прошел STAGE без критичных багов.
- Базовый smoke зеленый.
- Есть быстрый план отката (переменная окружения/конфиг готова).
