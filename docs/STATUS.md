# Статус: комментарии, лайки, сториз, модули

## Что уже готово

| Функция      | БД (таблица)   | Модуль сервера        | API                          | Клиент                    |
|-------------|-----------------|------------------------|------------------------------|---------------------------|
| **Комментарии** | ✅ `post_comments` | ✅ `server/comments/routes.ts` (~105 строк) | GET/POST `/api/posts/:postId/comments` | CommentsModal, от имени пользователя |
| **Лайки (реакции)** | ✅ `post_reactions` | ✅ `server/reactions/routes.ts` (~55 строк) | GET в ленте, POST/DELETE `/api/posts/:postId/reactions` | Посты + профиль: выбор эмодзи, сохранение в БД |
| **Сториз**  | ✅ `stories`    | ✅ `server/stories/` (routes thin + service) | GET `/api/users/:userId/stories`, POST/DELETE `/api/stories`, feed, viewers | Профиль: загрузка сториз по пользователю |

- **Посты**: таблица `posts`, модуль `server/posts/`, лента и создание поста.
- **Профиль**: аватар, имя, фамилия, пол, посты, сториз, реакции — данные из БД/API.

## Что нужно сделать один раз

1. **Применить схему БД**  
   Таблицы `post_reactions` и `stories` описаны в `shared/schema/`. Чтобы они появились в PostgreSQL, выполните:
   ```bash
   npm run db:push
   ```
   (Таблица `post_comments` уже должна быть в БД.)

2. **Модули и лимит 200 строк**  
   - У каждой функции свой модуль: `posts`, `comments`, `reactions`, `stories`.  
   - Файлы маршрутов сервера держим ≤200 строк.  
   - Реакции вынесены в отдельный модуль `server/reactions/`.

## Структура модулей (сервер)

- `server/posts/` — лента (GET), создание поста (POST). В ответе ленты — агрегат реакций из `post_reactions`.
- `server/comments/` — список и добавление комментариев к посту.
- `server/reactions/` — поставить/убрать реакцию на пост (POST/DELETE).
- `server/stories/` — список сториз пользователя, создание, удаление.

Файлы: по одному основному файлу маршрутов на модуль, при необходимости разбивать на подфайлы (например, хелперы запросов) так, чтобы каждый файл был не более 200 строк.
