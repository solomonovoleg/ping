# EDGE — два типа рейтингов, призы и заморозка

Зафиксированные продуктовые правила (для реализации в микросервисе EDGE, борде создателя и Companion). **Текущий код** может отличаться: один общий `xp` и один экран лидерборда — эта спека задаёт целевую модель.

---

## 1. Два независимых рейтинга

| Рейтинг | Смысл | Источник баллов (целевая модель) |
|--------|--------|----------------------------------|
| **Основной** | Игроки сортируются по очкам за активность **вокруг персонажа и игровых заданий** кампании (кормления, тапы, скрипты `edge_game_*`, задания EDGE без «глобального» соц-слоя и т.п.). | Отдельный счётчик (условно **игровой XP**), не смешивать с социальным без явного правила. |
| **Дополнительный** | Игроки сортируются по очкам за **действия на основной платформе** (приглашения, пост, сториз, комментарий, лайк и т.д. — набор настраивается). Проверка факта — на платформе; начисление по согласованному API. | Отдельный счётчик (условно **активность / социальные очки**), **не** зависит от сортировки основного рейтинга. |

У каждого рейтинга **свой** способ получения баллов и **своя** таблица позиций (два независимых числа на участника в рамках кампании).

---

## 2. Включение / выключение в настройках кампании

- У **основного** рейтинга — флаг **вкл/выкл** (аналог расширения текущего `leaderboard_global_enabled` или отдельное поле в `config_json`).
- У **дополнительного** — отдельный флаг **вкл/выкл**.

Рекомендуемые ключи в `edge_campaigns.config_json`:

- `leaderboards.primary.enabled: boolean`
- `leaderboards.secondary.enabled: boolean`
- `leaderboards.primary.label: string` (опционально, для UI)
- `leaderboards.secondary.label: string` (опционально, для UI)
- `leaderboards.primary.freeze.state: "active" | "frozen"`
- `leaderboards.secondary.freeze.state: "active" | "frozen"`
- `leaderboards.primary.freeze.frozenAt: string | null` (ISO)
- `leaderboards.secondary.freeze.frozenAt: string | null` (ISO)

**UI Companion (свайп-разделы):**

- Если включён **только основной** — одна страница «Рейтинг» (как сейчас по смыслу).
- Если включён **только дополнительный** — одна страница под этот рейтинг (или переименование/лейбл под продукт).
- Если включены **оба** — **вторая страница** в пейджере: две вкладки/два слайда «Рейтинг» (основной и дополнительный), порядок и подписи задаются в настройках (`surfaceOrder` / метаданные поверхностей).

Если оба выключены — блоки лидерборда в Companion не показываются (или скрыты по флагам).

## 3. Приз: в каком рейтинге участвует

При добавлении/редактировании приза (шаблон в `gifts_json` или связанная сущность) создатель указывает:

- участие в **основном** рейтинге (да/нет);
- участие в **дополнительном** рейтинге (да/нет);

Допустимы варианты: только основной, только дополнительный, оба, ни один (если приз выдаётся не из рейтинга — по отдельным правилам).

Это влияет на **правила розыгрыша** (например: «топ-N по основному», «топ-N по дополнительному», «случайно среди набравших минимум X в дополнительном»).

Рекомендуемая структура объекта приза в `gifts_json.templates[]`:

- `key: string`
- `title: string`
- `description?: string`
- `imageUrl?: string`
- `videoUrl?: string`
- `quantity?: number`
- `leaderboardScopes?: ("primary" | "secondary")[]` — в каком рейтинге(ах) участвует
- `drawAt?: string | null` — момент подведения итогов для этого приза (ISO)
- `selectionRule?: string` — человеко-читаемое правило отбора (для UI/модерации)

## 4. Момент выдачи приза и заморозка рейтинга

При настройке приза создатель задаёт **момент (событие) выдачи**, например:

- фиксированная дата/время;
- или «по кнопке создателя / админа»;
- или этап кампании (описывается в продуктовом DSL правил).

**В момент наступления выдачи по этому призу:**

1. Выполняется расчёт победителей по привязанному рейтингу(ам) и правилам.
2. Для **каждого рейтинга, который задействован в выдаче этого приза**, состояние рейтинга переходит в **«заморожен»**: новые баллы **не** изменяют позиции до явного действия создателя.

**Сброс заморозки** — только **вручную** создателем в настройках кампании (кнопка/действие «Снять заморозку рейтинга» / «Начать новый период» для основного и/или дополнительного отдельно, в зависимости от продукта).

После сброса:

- либо обнуляются очки периода и начинается новый сезон;
- либо только снимается freeze, а очки копятся дальше — **уточняется при реализации** (рекомендация: явно хранить «период» + снимок на момент награды в архиве).

Заморозка привязана к **логике кампании**: если один приз заморозил «дополнительный» рейтинг, другой приз в тот же период может использовать тот же замороженный снимок или ждать сброса — правила фиксируются в движке призов (не дублировать противоречия в этом файле без решения).

## 5. Связь с текущей реализацией

### 5.1. Уже в коде (EDGE + борд)

- Два счётчика: **`primary_xp` / `secondary_xp`**, лидерборд с `kind`, заморозка по **`primary_leaderboard_frozen_at` / `secondary_leaderboard_frozen_at`**.
- Пауза по **дате приза** (`gifts_json.templates[].drawAt` + `leaderboardScopes`): пока дата в прошлом, начисление в затронутый рейтинг блокируется, пока создатель не выставит в `config_json` флаг **`leaderboards.{primary|secondary}.prizeDrawRankingFreezeLifted`** (кнопка на борде) и/или не сбросит колонки заморозки через PATCH.
- При **успешном POST prize-draw** для выбранного приза в БД выставляется **`now()`** на соответствующие колонки заморозки по **`leaderboardScopes`** приза (если scopes пусты — оба рейтинга).
- При сохранении списка призов сброс **`prizeDrawRankingFreezeLifted`** делается **точечно**: только для рейтинга, у которого изменилось «расписание» призов, затрагивающих этот рейтинг (отпечаток по датам/scopes). В том же запросе, где создатель явно поднимает lift, этот флаг для соответствующего рейтинга не затирается.

### 5.2. Дальше по желанию

- Любые новые пути начисления очков — проверять **`effectiveLeaderboardXpFrozen`** для нужного `kind`.
- `edge_prize_winners` / сезоны — при необходимости метаданные снимка рейтинга.

## 6. Чеклист реализации (кратко)

- [ ] Схема: два счётчика или `edge_leaderboard_scores(kind)` + флаги включения.
- [ ] `campaign-config`: флаги + при необходимости порядок/лейблы двух экранов.
- [ ] Companion: второй слайд/вкладка при двух включённых рейтингах.
- [ ] Шаблон приза: поля «участвует в основном / дополнительном».
- [ ] Приз: поле «момент выдачи» + связь с заморозкой соответствующего(их) рейтинга(ов).
- [ ] Настройки создателя: ручной сброс заморозки / новый период.
- [ ] Документировать в `EDGE_DATABASE.md` после миграций.
