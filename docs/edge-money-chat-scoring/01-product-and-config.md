# Блок 1 — Продукт и конфигурация

Цель: зафиксировать поведение для создателя и формат данных до написания кода.

---

## 1.1. Поведение для участника

- Учитываются **исходящие сообщения** пользователя в **личных диалогах 1:1** с другим человеком (не группа).
- **Единица учёта — диалог** = один `chat_id` на платформе. Счётчик сообщений **ведётся отдельно по каждому чату** (не «10 сообщений суммарно по всем контактам»).
- За каждые **`threshold`** сообщений **в этом же чате** начисляется **`points`** XP в рейтинг кампании MONEY (тот же целевой столбец, что и у остальных money-правил: при включённом доп. рейтинге — в него).
- За **календарные сутки** сумма начислений по этому правилу **не превышает** значения, заданного создателем (**дневной потолок**).

Исключения (уточнить в ТЗ до реализации):

- Сообщения к ботам / сервисным чатам — не считать.
- Типы сообщений: только `text` или также голос/вложения — одно правило на продукт.

## 1.2. Поля правила `chat_messages` в `config_json.money.scoringRules`

Уже есть: `id`, `kind`, `threshold`, `points`, `enabled`.

**Добавить:**

| Поле | Тип | Смысл |
|------|-----|--------|
| `maxPointsPerDay` | number | Максимум XP по этому правилу за сутки на одного участника; `0` трактовать как «без лимита» (или запретить в UI — выбрать одно). |

Ограничения валидации (сервер + борд):

- `threshold` ≥ 1, `points` ≥ 0.
- `maxPointsPerDay` ≥ 0, разумный верхний предел (например ≤ 1_000_000) для защиты от опечаток.

## 1.3. EDGE: типы и парсинг

Файлы (текущие точки расширения, файлы держать короткими):

- `EDGE/money/types/money-config.ts` — поле в `MoneyScoringRule`.
- `EDGE/money/config/parse-money-config.ts` — чтение `maxPointsPerDay` с дефолтом.
- `EDGE/money/creator/merge-money-patch.ts` — нормализация при PATCH создателя.

При невалидном значении — отбросить поле или отклонить PATCH (единая политика с остальными правилами).

## 1.4. Клиент: борд (мастер «Баллы»)

- `client/src/lib/edge-money-wizard.ts` — при сериализации в PATCH добавить `maxPointsPerDay` для карточки `chat_messages`.
- UI карточки «Сообщения в чате»: три числа — порог, баллы за шаг, макс. баллов за день; подсказка одной строкой про «по каждому диалогу отдельно».

Не раздувать один компонент: при росте формы вынести поля в `features/edge-money-board/chat-messages-fields/` (или аналог), **≤250 строк на файл**.

## 1.5. Несколько кампаний MONEY у одного пользователя

Открытый продуктовый выбор (закрыть до блока 2–3):

- **Вариант A:** начислять во **все** опубликованные money-кампании, где пользователь — участник EDGE (дороже по запросам).
- **Вариант B:** только кампании с «активным» контекстом (сложнее определить).
- **Вариант C (v1):** ограничить продуктово «одна активная игра на пользователя» — не в коде, а политикой создателей.

В плане реализации заложить **явный выбор** в сервисном слое, чтобы не переписывать счётчики позже.
