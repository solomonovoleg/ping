Список того, что стоит доработать для стабильности и предсказуемого поведения.

## 1. WebSocket: подписки при первом открытии (низкий риск)

**Поведение:** При первом заходе в приложение WebSocket подключается с задержкой 300 ms. Подписки `subscribe-chat` отправляются только в `onopen` (один раз при открытии сокета) и только при добавлении первого слушателя на чат — дублирование устранено в соответствии с `AI_HANDOFF_ARCHITECTURE.md`.

**Что может быть не так:** В очень быстром сценарии (открыл чаты до `onopen`) первые 1–2 секунды события (новые сообщения, «печатает») могут не приходить, пока не сработает `onopen`.

**Рекомендация:** При желании можно показывать тонкий индикатор «подключение…» пока `ws.readyState !== 1`.

## 2. Отметка «прочитано» и обновление чата при visibilitychange

**Код:** `ChatDetail.tsx` — при `visibilitychange` вызываются `PUT /chats/:id/read` и `GET /chats/:id`. Ошибки глотаются: `.catch(() => {})`.

**Поведение:** Если запрос падает (сеть, 5xx), пользователь не видит ошибки; непрочитанные могут не сбрасываться или данные чата не обновятся.

**Рекомендация:** Для стабильности не обязательно показывать тост (чтобы не спамить), но в dev можно логировать: `console.warn("[chat] read/refresh failed", err)`. Для прода — оставить тихий fail, при необходимости добавить повторную попытку (retry) или фоновый refetch при следующем фокусе.

## 3. Регистрация FCM-токена (пуши)

**Исправлено.** В `AuthContext.tsx` при ошибке получения токена (`requestPushAndGetToken`) или при ошибке отправки на сервер (`POST .../users/me/push-token`) показывается тост «Не удалось включить уведомления».

## 4. Сессия (вход/регистрация)

**Было:** Ошибка «Ошибка сохранения сессии» при отсутствии или сбое таблицы сессий в PostgreSQL.

**Сделано:** Таблица `session` создаётся при старте (`ensureSessionTable`), ошибки сохранения сессии логируются на сервере.

**Рекомендация:** После деплоя убедиться, что на сервере в логах нет `[auth] session save failed`. Если ошибка появляется — смотреть полный текст в логах (права на таблицу, доступ к БД).

---

## 5. Звонки (WebRTC)

**Поведение:** При обрыве соединения или ошибке simple-peer вызывается `endCall()`, показывается «Ошибка соединения». Поведение нормальное. Много пустых `catch` в `useCall.ts` и `incoming-call-alert.ts` — ошибки не показываются пользователю.

**Рекомендация:** Критичные ошибки (например, не удалось получить медиа-поток, не удалось установить соединение) уже пробрасываются через `setError`. Остальные catch можно оставить тихими, но при отладке добавлять `console.error` в нужных местах.

---

## 6. Список чатов после длительного фона

**Поведение:** При возврате на вкладку/приложение срабатывает `ping:chat-list-update` (если пришло новое сообщение по WebSocket), и `AppLayout` делает `invalidateQueries(["chats"])` — список перезапрашивается. Если WebSocket был разорван и переподключился, подписки восстанавливаются в `onopen`, так что обновления снова приходят.

**Рекомендация:** При долгом простое (например, телефон в режиме сна) браузер может закрыть WebSocket. Сейчас при `onclose` вызывается переподключение через 2 s. Можно добавить при возврате на вкладку (например, по `visibilitychange` или `focus`) проверку: если `ws.readyState !== 1`, один раз триггерить переподключение раньше — опционально.

## Итог по приоритетам

| Приоритет | Что | Действие |
|-----------|-----|----------|
| Высокий   | Сессия не сохраняется | Уже исправлено (таблица + логи). Проверить после деплоя. |
| Средний   | Пуш-токен не регистрируется тихо | Исправлено: тост «Не удалось включить уведомления» при ошибке получения или отправки токена. |
| Низкий    | Отметка «прочитано» / обновление чата при visibility | Логировать в dev; при необходимости добавить retry. |
| Низкий    | WebSocket при первом открытии | Обработано: подписки только в onopen, deduplicated subscribe-chat. |
| Низкий    | Быстрое переподключение при возврате в приложение | По желанию: при focus/visibility проверять сокет и переподключать. |

Если нужно, можно по шагам расписать реализацию по любому пункту (например, тост при ошибке пуша или retry для read).
