# Ручная приёмка: скорость и «уверенность» UI (чат и список)

Короткий чеклист после изменений в чате, списке чатов и связанном API. Детали дорожной карты: [`PERFORMANCE_CONFIDENCE_FORWARD_ROADMAP.md`](./PERFORMANCE_CONFIDENCE_FORWARD_ROADMAP.md).

1. Холодный заход на `/chats` — есть скелетон/контент, не пустой экран >200 ms без пояснения.
2. Тап по чату — сообщения или офлайн-снимок; при ошибке — текст и «Повторить».
3. Догрузка истории вверх — позиция скролла не «прыгает» необъяснимо.
4. Отправка текста — оптимистичное появление, при ошибке — тост или failed state.
5. Голосовое — индикатор до метаданных; после ошибки — «Повторить»; цепочка «следующее» не ломается.
6. Видеокружок — на первом тапе видно ожидание до старта; ошибка URL — retry.
7. Реконнект WS (симуляция offline) — хвост подтягивается или виден тост об ошибке обновления.
8. Поиск по сообщениям из списка чатов — повторный тот же запрос не должен бить сеть без нужды (staleTime / кэш).
9. Список чатов при фоновом refetch — полоска/индикатор синхронизации (если включён).
10. Network throttling 3G — чат открывается без «немого» зависания сверх таймаута из констант.
11. Длинный тред (200+ сообщений) — скролл приемлемый; см. ограничения в [`CHAT_THREAD_VIRTUALIZATION.md`](./CHAT_THREAD_VIRTUALIZATION.md).
12. Нет полных presigned URL в серверных логах продакшена (grep по логам после деплоя).
