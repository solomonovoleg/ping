# Бэклог UI/UX: PING MOOT (веб + мобильное приложение)

**Назначение:** список улучшений интерфейса по приоритету. Внутренний бэклог, не вердикт — что доделать для большей полировки и доверия.  
**Объём:** веб-клиент (`client/src`), мобильное приложение (`mobile/`).

---

## 1. Загрузка и обратная связь

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб: Лента (Posts)** | При загрузке ленты показывается только текст «Загрузка ленты…» без скелетона или спинера. Компонент `Skeleton` есть в проекте, но на ленте не используется. |
| **Веб: Чаты (Chats)** | «Загрузка чатов...» — текстовый блок по центру, без скелетона списка чатов. |
| **Веб: Детали чата (ChatDetail)** | «Загрузка чата...» + кнопка «Назад». Нет скелетона заголовка и пузырей сообщений. |
| **Веб: Глобальный поиск (GlobalSearch)** | В выпадающем списке при поиске — только «Поиск...» и «Никого не найдено» текстом, без индикатора загрузки (спинера) в дропдауне. |
| **Веб: App (инициализация)** | При `isLoading` auth — только «Загрузка...» по центру, без логотипа и без скелетона layout. |
| **Веб: Настройки — приглашения** | Блок «Приглашения» при загрузке показывает «Загрузка…» без скелетона карточек. |
| **Мобильное: Лента** | Полноэкранный `ActivityIndicator` без скелетона. При pull-to-refresh — только индикатор, контент пропадает. |
| **Мобильное: Чаты** | «Загрузка чатов...» + спиннер, без скелетона строк чатов. |
| **Мобильное: Профиль** | При первой загрузке — только спиннер, без скелетона аватара и блоков. |
| **Мобильное: Чат [id]** | При загрузке чата/сообщений нет явного полноэкранного loading (данные подставляются по мере прихода). |

### Рекомендации

- **Быстрые победы:**  
  - На ленте (веб и мобильное): показывать 3–5 карточек-скелетонов поста (аватар + линии текста + прямоугольник медиа) вместо одного текста «Загрузка…».  
  - В списке чатов: 5–7 строк-скелетонов (круг + две линии) вместо только текста.  
  - В GlobalSearch: в выпадающем списке при `loading` показывать `<Spinner />` или 3 строки-скелетона.  
  - При инициализации приложения (auth): оставить логотип + под ним спиннер или минимальный скелетон (полоска под логотипом).

- **Более крупные изменения:**  
  - Ввести единый компонент экрана загрузки (например, `PageSkeleton`) с вариантами для ленты, чатов, профиля и переиспользовать его в вебе и, по возможности, в мобильном (аналог скелетона на RN).  
  - При pull-to-refresh не скрывать список, а показывать индикатор сверху и сохранять текущий контент.

## 2. Пустые состояния (Empty states)

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб: Чаты** | Пустое состояние с иконкой, заголовком и подсказкой есть и выглядит хорошо. Но при пустом списке по поиску текст «Нет чатов по запросу» — без отдельной иллюстрации или CTA «Очистить фильтр». |
| **Веб: Лента** | Только текст «Пока нет постов» по центру — нет иконки/иллюстрации, нет CTA «Создать первый пост» или «Перейти в профиль». |
| **Веб: Контакты** | «Пока нет контактов» + подсказка есть; можно усилить иллюстрацией и кнопкой «Найти в поиске». |
| **Веб: 404 (NotFound)** | Текст на английском («404 Page Not Found», «Did you forget to add the page to the router?»), не адаптирован под продукт и русский язык. |
| **Веб: Комментарии (CommentsModal)** | При пустом списке — только «Загрузка» или пусто; нет явного «Пока нет комментариев» с дружелюбной формулировкой. |
| **Мобильное: Лента** | `ListEmptyComponent`: только «Пока нет постов» — без иконки и CTA. |
| **Мобильное: Чаты** | Есть эмодзи 💬, заголовок и подзаголовок — хорошо; можно добавить одну кнопку «Найти человека». |
| **Мобильное: Профиль** | «Нет записей» — один текст, без иконки и призыва добавить запись (для своего профиля). |

### Рекомендации

- **Быстрые победы:**  
  - Лента (веб и мобильное): добавить иконку/иллюстрацию (например, PenSquare или нейтральную картинку) + «Пока нет постов» + кнопка «Написать первый пост» → переход на создание поста.  
  - 404: перевести на русский, заменить текст на пользовательский («Страница не найдена», «Вернуться в чаты» / «На главную»).  
  - Профиль (мобильное): для своего профиля в пустом состоянии добавить «Нет записей» + кнопку «Добавить запись».

- **Более крупные изменения:**  
  - Использовать общий компонент `Empty` (уже есть в `client/src/components/ui/empty.tsx`) везде: EmptyMedia, EmptyTitle, EmptyDescription, EmptyContent + опциональная кнопка CTA.  
  - Завести 2–3 иллюстрации (или лаконичные SVG) для «нет чатов», «нет постов», «ничего не найдено» и подставлять их в Empty.

## 3. Ошибки и валидация

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб: Чаты** | При ошибке загрузки чатов (useQuery error) пользователь не видит явного сообщения об ошибке и кнопки «Повторить» — список просто пустой или в старом состоянии. |
| **Веб: Лента** | При ошибке запроса ленты — пустой список без сообщения и без retry. |
| **Веб: ChatDetail** | При ошибке или отсутствии чата показывается текст ошибки и кнопка «Вернуться к чатам» — хорошо; но кнопки «Повторить попытку» нет. |
| **Веб: Login** | Валидация телефона и пароля есть, ошибки выводятся под полями и общий error под формой. При loading кнопка показывает «...» — ок. |
| **Веб: CreatePost** | Есть `error` под полями и toast при ошибке публикации. Нет валидации длины текста и лимита размера файла с понятным сообщением до отправки. |
| **Веб: Onboarding** | Ошибки сабмита показываются текстом; нет подсветки невалидных полей (например, красная обводка). |
| **Веб: GlobalSearch** | При ошибке поиска — только toast «Ошибка поиска»; в выпадающем списке можно оставить краткое «Не удалось выполнить поиск. Повторите.» + кнопку повтора. |
| **Мобильное: Чаты** | При ошибке загрузки показывается полноэкранный текст ошибки без кнопки «Повторить». |
| **Мобильное: Лента** | При ошибке load() список остаётся пустым, без баннера ошибки и retry. |
| **Мобильное: Login** | Ошибка под формой есть; нет подсветки невалидного поля (border/background). |
| **Мобильное: CreatePost** | Ошибки только через `Alert.alert`; при пустом тексте — alert «Введите текст записи». Нет inline-ошибки под полем. |

### Рекомендации

- **Быстрые победы:**  
  - Чаты (веб): при `isError` от useQuery показывать блок «Не удалось загрузить чаты» + кнопка «Повторить» (refetch).  
  - Лента (веб и мобильное): при ошибке загрузки показывать сверху или по центру сообщение + «Повторить».  
  - ChatDetail (веб): на экране ошибки добавить кнопку «Повторить» (повторный запрос чата).  
  - Мобильное: Чаты — под текстом ошибки кнопка «Повторить» с вызовом повторного load().  
  - Onboarding (веб): при наличии `error` подсвечивать невалидные поля (например, `border-destructive` или `ring-destructive`).

- **Более крупные изменения:**  
  - Ввести общий компонент «ошибка с повтором» (ErrorWithRetry): иконка, текст, кнопка «Повторить» и опционально «На главную». Использовать на всех экранах со списками и деталями.  
  - CreatePost: лимиты (макс. длина текста, макс. размер файла) и показ ошибок до сабмита (под полем / под кнопкой загрузки).  
  - Мобильное: единообразно использовать либо Alert для критичных ошибок, либо inline-блок под формой + кнопка «Повторить» для сетевых ошибок.

## 4. Типографика и иерархия

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб** | В `index.css` заданы токены (--uix-text-title, --uix-text-list-primary и т.д.), но в компонентах часто используются жёсткие значения: `text-2xl`, `text-[15px]`, `text-[17px]`, `text-[10px]`. Иерархия не сводится к одной шкале. |
| **Веб: заголовки экранов** | «Чаты», «Лента», «Настройки» — разный размер/начертание (например, `text-xl` vs `text-2xl`), нет единого стиля «заголовок экрана». |
| **Веб: списки** | Имена в чатах/ленте — `text-[15px]`/`text-[16px]`, вторичный текст — `text-xs`; в целом читаемо, но шкала не формализована. |
| **Мобильное** | В `theme.ts` есть `typography` (title, listPrimary, listSecondary, caption, input); в стилях используются и эти значения, и захардкоженные fontSize (12, 14, 15, 16, 17, 22 и т.д.). |
| **Веб: not-found** | Заголовок и текст на английском, шрифт/цвет (gray-900, gray-600) не через CSS-переменные темы. |

### Рекомендации

- **Быстрые победы:**  
  - Ввести класс-хелперы под токены: например, `.uix-title`, `.uix-list-primary`, `.uix-caption` и использовать их для заголовков экранов и списков.  
  - Страницу 404 перевести на русский и перевести на `text-foreground` / `text-muted-foreground` и размеры из темы.

- **Более крупные изменения:**  
  - Провести ревизию всех `text-*` и `font-*` в ключевых страницах и заменить на классы из единой типографической шкалы (как в UIX_AUDIT.md, если есть).  
  - В мобильном: заменить «магические» fontSize на константы из `theme.typography` и при необходимости расширить шкалу (например, subtitle, overline).

## 5. Отступы и компоновка

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб** | Токены отступов (--uix-space-1 … --uix-space-8) есть, но в разметке часто используются произвольные значения: `p-4`, `gap-2`, `py-2.5`, `mb-4`, `px-3` и т.д. Ритм не везде выдержан. |
| **Веб: нижняя навигация** | Высота и отступы (h-14, pb-safe) заданы; логотип по центру — ок. Размер иконок и подписей местами различается (например, `text-[10px]`). |
| **Веб: карточки постов/чатов** | Разный padding у карточек поста и у строк чата (p-4 vs py-2 px-2.5), что допустимо, но стоит проверить по сетке (например, шаг 4px/8px). |
| **Мобильное** | `spacing` из theme используется (space2, space3, space4…); в ряде мест отступы заданы числами (8, 12, 16) без констант — мелочь, но для консистентности лучше везде theme. |
| **Мобильное: таб-бар** | Высота и safe area учтены; иконки и подписи выровнены. Минимальная высота таба чуть меньше 44pt (touchMin - 8) — может быть на грани a11y. |

### Рекомендации

- **Быстрые победы:**  
  - В вебе: на 2–3 ключевых экранах (Чаты, Лента, Настройки) заменить произвольные отступы на классы из шкалы (например, `p-[var(--uix-space-4)]`, `gap-[var(--uix-space-2)]`).  
  - В мобильном: в CustomTabBar поднять minHeight таба до полных `spacing.touchMin` (44) для уверенного тапа.

- **Более крупные изменения:**  
  - Описать в одном месте (документ или Storybook) правила: «заголовок экрана — отступ снизу space-2», «список — padding horizontal space-4», «карточка — padding space-4» и т.д., и постепенно унифицировать.

## 6. Движение и полировка

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб: кнопки** | У кнопок в AppLayout и части страниц есть `active:scale-95` и transition; у части кнопок (например, в Settings — «Изм.», иконки) нет явного hover/active состояния. |
| **Веб: навигация** | Переход между экранами без анимации (wouter меняет компонент мгновенно). CreatePost и ChatDetail используют `animate-in slide-in-from-*` — хорошо. |
| **Веб: списки** | Нет анимации появления элементов (stagger) при загрузке чатов/постов; список просто «проявляется». |
| **Веб: модальные окна** | CommentsModal, CallModal — проверить наличие открытия/закрытия с transition (например, fade + scale). |
| **Мобильное: табы** | Смена активного таба без анимации; только смена цвета подписи/иконки. Нет тактильной обратной связи (haptic) при переключении. |
| **Мобильное: кнопки** | TouchableOpacity с activeOpacity 0.7 в части мест; в других — без явного feedback. Кнопка «Выйти» в Settings без визуального отклика при нажатии. |
| **Веб: форма Login** | Кнопка при loading показывает «...», но без состояния disabled с визуальным отличием (уже есть disabled:opacity-50). |

### Рекомендации

- **Быстрые победы:**  
  - Все интерактивные кнопки и иконки в навигации и в хедерах: единообразно добавить `hover:bg-secondary/50` или `hover:bg-primary/10` и `active:scale-95` (веб).  
  - Мобильное: для основных кнопок (Войти, Опубликовать, Выйти) задать `activeOpacity={0.7}` и при желании добавить лёгкий haptic при тапе (expo-haptics).  
  - Мобильное: при переключении табов вызывать лёгкую вибрацию (Haptics.selectionAsync).

- **Более крупные изменения:**  
  - Веб: общий layout-переход при смене маршрута (например, мягкий fade или slide на 150–200 ms).  
  - Списки: при первой загрузке показывать скелетоны, затем заменять на контент с опциональным stagger (например, opacity 0→1 с небольшой задержкой по индексу).

## 7. Доверие и ясность

### Что можно улучшить

| Где | Что улучшить |
|-----|---------------|
| **Веб: Login** | Под логотипом есть слоган «Персональный мессенджер! Максимальная приватность» — хорошо. Нет явной формулировки про «безопасность» или «данные не передаются третьим лицам» (как у Telegram). |
| **Веб: 404** | Английский текст и техническая фраза «Did you forget to add the page to the router?» снижают доверие и выглядят как отладочная страница. |
| **Веб: Настройки — профиль** | В карточке профиля захардкожен текст «Создаю интерфейсы…» — выглядит как тестовый контент; у пользователя должен быть свой статус/био или поле «О себе». |
| **Веб/мобильное: нет «verified»** | Нет индикации верифицированных или официальных аккаунтов (если продукт планирует такие роли). |
| **Веб: пароль при регистрации** | Нет подсказки о требованиях к паролю (например, «не менее 6 символов») под полем до первой ошибки. |
| **Мобильное: Login** | Тот же слоган есть; нет короткой строки про безопасность/шифрование. |
| **Веб: Onboarding** | После заполнения профиля пользователь сразу попадает в приложение; нет экрана «Всё готово» или краткого онбординга (как в Telegram — «ваш номер виден только тем, у кого вы в контактах»). |

### Рекомендации

- **Быстрые победы:**  
  - 404: русский текст, нейтральное сообщение и кнопки «На главную» / «В чаты».  
  - Настройки: убрать захардкоженный статус; показывать реальное поле «О себе» из профиля или placeholder «Расскажите о себе».  
  - Login (веб и мобильное): под формой одна строка, например: «Мы не передаём ваш номер третьим лицам» или «Регистрация только по приглашению».  
  - Регистрация: под полем пароля сразу показывать подсказку «Не менее 6 символов».

- **Более крупные изменения:**  
  - После онбординга: один экран «Готово» с кратким описанием правил (приватность, приглашения) и кнопкой «Начать».  
  - При необходимости: бейдж «Официальный»/«Подтверждён» в профиле и в чатах (API + UI).  
  - Политика конфиденциальности и условия использования — ссылки в Login или в Настройках (даже статичная страница повышает доверие).

## Приоритизация

### Быстрые победы (1–2 дня)

1. **Загрузка:** скелетоны на ленте и в списке чатов (веб); спиннер/скелетон в GlobalSearch при поиске.  
2. **Пустые состояния:** лента — иконка + CTA «Написать первый пост»; 404 — русский текст и кнопки.  
3. **Ошибки:** кнопка «Повторить» при ошибке загрузки чатов и ленты (веб и мобильное).  
4. **Кнопки:** единообразный hover/active для навигации и заголовков (веб).  
5. **Доверие:** убрать захардкоженный статус в Настройках; 404 на русском; подпись под формой входа про приватность.

### Средний приоритет (до недели)

6. Единый компонент ErrorWithRetry и его использование на всех экранах со списками.  
7. Использование компонента Empty с иллюстрациями и CTA везде, где есть пустые списки.  
8. Типографика: классы по токенам и замена ad-hoc размеров на экранах Чаты, Лента, Настройки.  
9. Мобильное: улучшение empty states (иконки + CTA), кнопка «Повторить» при ошибках, haptic при табах.  
10. Валидация и лимиты в CreatePost с понятными сообщениями до отправки.

### Крупные улучшения (2+ недели)

11. Единый PageSkeleton для веба (и аналог для мобильного) с вариантами под ленту, чаты, профиль.  
12. Анимации переходов между экранами и появление списков (stagger).  
13. Полная унификация отступов по дизайн-токенам и документирование правил.  
14. Экран «Готово» после онбординга и, при необходимости, индикация верифицированных аккаунтов.
