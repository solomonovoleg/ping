# Смоук iSee (ручной)

Краткий чеклист после правок плеера, постеров или выката бэкфилла. Выполнять на **веб** (Chrome / Safari) и в **нативе** (iOS WebView / Android), если затронут Capacitor.

## Проверка постера и бэкфилла (SSH не обязателен)

### Постер `.jpg` по URL (без SSH)

Браузер для `<video poster="…">` ходит на **прямой публичный URL** без вашей сессии. Проверка с любой машины:

1. Откройте iSee в Chrome → **DevTools → Network** → фильтр **Img** или по строке `.jpg`.
2. Скопируйте URL запроса к постеру (или возьмите из ответа API поста поле `posterUrl`, если оно отдаётся клиенту).
3. В терминале:

```bash
curl -sI "https://ВАШ_ХОСТ/…/posts/UUID.jpg"
```

Ожидается **`HTTP/2 200`** (или `HTTP/1.1 200`) и заголовок вроде **`content-type: image/jpeg`**.

- **`403 Forbidden`** — объект в S3 не открыт на чтение для анонимов: политика бакета / ACL / `S3_PUBLIC_ACL` (см. **`docs/DEPLOY_RULES.md`**, §7).
- **`404`** — постер ещё не залит; для старых постов нужен **`npm run backfill:post-video-posters`** (см. ниже).

При желании то же в **приватном окне** (без кук сайта): если там 403, в ленте постер тоже не подтянется.

### Бэкфилл постеров (удобнее по SSH на VPS)

На сервере уже лежит собранный проект и **`.env`** с `DATABASE_URL` и `S3_*`. Типичный путь к коду — из **`deploy.env`**: **`VPS_PATH`** (см. **`docs/DEPLOY.md`**).

```bash
ssh user@ВАШ_VPS
cd /var/www/ping-moot   # или ваш VPS_PATH

# подтянуть актуальный код и зависимости, если бэкфилл ещё не в этом деплое
# git pull && npm ci   # по вашему процессу

npm run backfill:post-video-posters -- --dry-run
npm run backfill:post-video-posters -- --limit=100
```

Требования на машине, где крутится скрипт: **`ffmpeg`**, доступ к БД и к S3 теми же переменными, что у приложения. Локально на VPS для дисковых URL нужен каталог **`uploads/posts/`** от корня проекта — см. **`docs/MIGRATIONS_AND_DEPLOY_CHECKLIST.md`** §6.

**Без SSH:** можно запустить те же команды на CI или на своём ноутбуке, экспортировав в окружение **`DATABASE_URL`** и **`S3_*`** из защищённого хранилища (не коммитить в git).

## Базовый сценарий

1. Открыть **iSee** (`/reels` или вход из ленты постов).
2. **Вертикальный свайп** между роликами: активный слайд автоплеится, соседние не мешают звуком (по умолчанию звук выкл.).
3. **Постер**: до старта видео виден кадр-превью (JPEG), а не длительный чёрный экран (если для поста есть постер в S3/на диске).

## Модалки и пауза

4. Открыть **комментарии** к ролику: воспроизведение **на паузе**, закрыть — снова играет активный слайд.
5. Открыть **«Поделиться»** (или аналогичный шит): то же — **пауза**, после закрытия — возобновление.

## Сеть и ошибки

6. Включить **режим офлайна** (или оборвать сеть) на активном ролике: ожидается **ошибка** и кнопка **«Повторить»**; после восстановления сети повтор запускает загрузку.

## Нативные детали (по возможности)

7. **Хаптик**: короткий тап по области жестов — лёгкий отклик; длинное удержание скорости — средний (если включено в сборке).

## Телеметрия (опционально)

8. На стенде с авторизованным пользователем: после нескольких слайдов с первым кадром в **Админка → Ops → Модули** появляются строки **«Клиент: iSee time-to-first-play»** (агрегат с момента рестарта процесса; на клиенте throttling 10 с и лимит 40 событий за сессию вкладки).
