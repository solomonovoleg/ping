# Версионирование WebSocket и публичного API (процесс)

## Принцип

Ломающие изменения в формате событий или полей **не выкатывать без** совместимого переходного периода или фича-флага на клиенте и сервере.

## WebSocket (чат, звонки)

- Контракты раздельно: звонки (`shared` handshake, клиент `features/call`), чат (`useChatRealtime`, серверные обработчики).
- Новое поле в payload: сначала **опционально** на сервере, затем чтение на клиенте, затем обязательность.
- Переименование типа события: ввести новый тип, дублировать старый на один релиз, залогировать использование старого, удалить в следующем.

## REST

- Предпочтительно новые query/поля вместо смены семантики существующих.
- Агрегаты вроде `GET /chats/:id/bootstrap` — отдельный путь и флаг (`VITE_CHAT_BOOTSTRAP`), пока клиент и сервер не согласованы.

## Чеклист перед merge

1. Старые клиенты не получают 500 из-за нового обязательного поля.
2. В `AGENTS.md` или журнале `PROJECT_MAP.md` — строка о смене контракта, если затронуты внешние клиенты.
