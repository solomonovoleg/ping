# Мультисервис: логи, request id, здоровье

Краткая памятка для платформы (монолит), EDGE и PARSER.

## Корреляция запросов (`X-Request-Id`)

- Платформа выставляет **`X-Request-Id`** на каждый входящий HTTP-ответ (и принимает входящий заголовок от клиента, если он короткий и безопасный).
- При проксировании в **EDGE** и **PARSER** с пользовательских маршрутов платформа пробрасывает тот же id в исходящий **`X-Request-Id`**, чтобы в логах микросервисов можно было сопоставить цепочку с `[rid:…]` в логах Node.

**Как искать:** в логах PM2/nginx/консоли ищите один и тот же UUID (или значение из заголовка) на платформе и на стороне EDGE/PARSER за то же время.

## Падение EDGE или PARSER

1. Убедиться, что процессы живы на сервере (PM2 / unit — как у вас заведено).
2. Проверить переменные **`EDGE_UPSTREAM_URL`** / **`PARSER_UPSTREAM_URL`** и секреты сервис-сервис (**`EDGE_SERVICE_SECRET`**, **`PARSER_SERVICE_SECRET`**) на платформе — см. **`docs/DEPLOY_RULES.md`**.
3. Платформа: **`GET /api/edge/health`** — флаг `companionBackend` (доступность EDGE по health).
4. Общий лиминальный пинг приложения: **`GET /api/health`** — `{ ok, uptimeSec }` без секретов.

## После выката

- В логах платформы не должно идти непрерывной чередой **`[auth] session save failed`** (если есть — БД/диск сессий, см. **`docs/DEPLOY_RULES.md`** про `DATABASE_URL` и `connect-pg-simple`).
