# Улучшения и оптимизации кода

## Сделано

### 1. Code splitting (ленивая загрузка страниц)
- **Файл:** `client/src/App.tsx`
- Тяжёлые страницы подгружаются по мере перехода: `ChatDetail`, `UserProfile`, `PostDetail`, `EditProfile`, `CreatePost`, `Board`, `Settings`, `Subscribers`, `AdminApp`.
- Главный экран (Чаты, Лента) и `Login`/`Onboarding` остаются в начальном бандле — быстрый первый экран.
- При переходе на маршрут показывается спиннер (`PageFallback`), пока чанк грузится.
- **Эффект:** меньший начальный размер JS, быстрее загрузка при первом открытии.

### 2. Разделение вендорных чанков (Vite)
- **Файл:** `vite.config.ts` → `build.rollupOptions.output.manualChunks`
- Вынесены в отдельные чанки: `framer-motion`, `recharts`, `lucide-react`.
- **Эффект:** лучше кэширование (при обновлении кода приложения эти библиотеки не перекачиваются), предупреждение о размере чанка снижено до 600 KB.

### 3. Мемоизация строки чата
- **Файл:** `client/src/pages/Chats.tsx`
- Компонент `ChatRow` обёрнут в `React.memo`; в пропсах передаются только нужные данные (`chat`, `typingLabel`, `voiceLabel`, `onSelect`).
- **Эффект:** при обновлении «печатает»/«записывает голосовое» перерисовывается только одна строка, а не весь список чатов.

## Что оптимизировать и где решения не самые современные

### 1. Поиск (GlobalSearch) — ручной fetch вместо TanStack Query
- **Сейчас:** `useState` (results, loading, searchError) + `useEffect` с debounce + вызов `searchUsers(q)` вручную.
- **Минусы:** нет кэша по запросу, при повторном вводе того же текста запрос уходит снова; нет дедупликации; нет флага `isFetching` из коробки.
- **Современно:** `useQuery` с `queryKey: ["search", debouncedQuery]`, `enabled: !!debouncedQuery.trim()`, `staleTime: 30_000` — кэш, дедуп, повтор при фокусе по желанию.

### 2. Загрузка чата и сообщений — ручной fetch вместо Query
- **Сейчас:** в `useChatMessages` — `apiFetch` + `setChat`/`setMessages`/`setLoading`/`setError` вручную, таймауты и проверки `currentChatIdRef`.
- **Минусы:** нет общего кэша чатов (при переходе в другой чат и обратно — повторный запрос); нет встроенного background refetch и retry-политики из TanStack Query.
- **Современно:** `useQuery` для чата по `chatId`, `useInfiniteQuery` для сообщений (страницы вверх). Кэш, дедуп, отмена при размонтировании и смене id — автоматически.

### 3. Картинки — без lazy и декодинга
- **Где:** `PostMedia`, `ChatDetail` (фото в сообщениях, превью поста), `UserProfile`, `StoryViewer`, лента постов.
- **Сейчас:** обычные `<img src={...}>` без `loading="lazy"` и `decoding="async"`.
- **Минусы:** все картинки в viewport грузятся сразу; декодирование может блокировать main thread.
- **Современно:** `loading="lazy"` для изображений ниже fold (лента, галерея чата, профиль); `decoding="async"`; при желании — blur-placeholder или скелетон до `onLoad`.

### 4. React 19 — не используются новые примитивы
- **Сейчас:** React 19 в зависимостях, но без `useTransition`, `useDeferredValue`, `use()`.
- **Где применить:** тяжёлые обновления при открытии чата, фильтрация ленты, переключение вкладок — обернуть в `startTransition`, чтобы UI оставался отзывчивым; для отложенного ввода поиска — `useDeferredValue(query)`.
- **Эффект:** меньше «зависаний» при больших списках и смене экранов.

### 5. Список сообщений в чате — без виртуализации и мемо
- **Сейчас:** весь `messageListItems` рендерится в один скролл; каждый пузырь — инлайн JSX, без `React.memo`.
- **Минусы:** при 300+ сообщениях и частых обновлениях (печатает, новые сообщения) возможны лаги; любое обновление состояния перерисовывает весь список.
- **Современно:** вынести один элемент в `MessageBubble` с `React.memo`; при росте до 500+ сообщений — виртуализация (`@tanstack/react-virtual`) по скроллу.

### 6. Обработка ошибок (тихие catch)
- **Где:** см. `docs/UNSTABLE_OR_POORLY_WORKING.md` — push-token, `recordPostView`, read/refresh при `visibilitychange`, пуш-уведомления на сервере.
- **Не «устарело», но:** для критичных путей (пуши, отметка прочитанным) — тост или повторная попытка вместо пустого `.catch(() => {})`.

### Приоритеты (кратко)
| Приоритет | Что |
|-----------|-----|
| Высокий   | Lazy + decoding для картинок в ленте и чате; мемо для пузырей сообщений (`MessageBubble`). |
| Средний   | GlobalSearch на `useQuery`; чат/сообщения на `useQuery`/`useInfiniteQuery`. |
| Низкий    | `useTransition` для тяжёлых экранов; виртуализация списка сообщений при росте данных; PWA/офлайн. |
