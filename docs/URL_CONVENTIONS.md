# URL Conventions (Human-Readable)

Цель: короткие и понятные ссылки, единый стиль и предсказуемая навигация.

## Базовые принципы

- Канонический формат: короткие префиксы (`/u`, `/chat`, `/edge`), без лишней вложенности.
- Идентификаторы в URL: только стабильные публичные идентификаторы.
- Старые пути поддерживаются, но редиректятся на канонические.

## Канонические маршруты

| Сущность | Канонический путь | Пример |
|---|---|---|
| Профиль пользователя | `/u/:id` | `/u/5` |
| Свой профиль | `/u/me` | `/u/me` |
| Пост пользователя | `/u/:id/p/:postId` | `/u/5/p/2142` |
| Подписчики | `/u/:id/followers` | `/u/5/followers` |
| Подписки | `/u/:id/following` | `/u/5/following` |
| Диалог/чат | `/chat/:ref` | `/chat/5` (DM) или `/chat/a3f8b2c1` (group/business) |
| EDGE карточка | `/edge/:edgeId` | `/edge/cmp_9` |
| Лента | `/posts` | `/posts` |
| Сохранённые | `/saved` | `/saved` |
| Уведомления | `/notifications` | `/notifications` |

## Совместимость со старыми путями

- `/profile/:id` -> `/u/:id`
- `/profile/:id/post/:postId` -> `/u/:id/p/:postId`
- `/profile/:id/followers` -> `/u/:id/followers`
- `/profile/:id/following` -> `/u/:id/following`
- `/id/:id` -> `/u/:id`

## 20 улучшений ссылочного отображения

1. Канонизировать профили на короткий путь `/u/:id`.
2. Канонизировать посты на `/u/:id/p/:postId`.
3. Поддерживать совместимость старых `/profile/...` через редирект.
4. Держать единый короткий namespace сущностей (`u`, `p`, `edge`).
5. Исключить UUID из публичных ссылок там, где есть public id.
6. Сохранить `me`-сегмент для собственного профиля (`/u/me`).
7. Вынести единые route-builder функции и использовать их в UI.
8. Копировать из UI только канонические короткие ссылки.
9. Разрешать deep-link возврат после авторизации для новых `/u/...` URL.
10. Нормализовать и валидировать `back` query в внутренних переходах.
11. Запретить внешние `back`-URL (защита от open redirect).
12. Использовать URL только для идентичности ресурса, не для состояния UI.
13. Сохранять query-параметры при редиректах, если они безопасны.
14. Обеспечить idempotent-редиректы (всегда один финальный canonical URL).
15. Не смешивать разные форматы поста (`/post/` и `/p/`) в каноне.
16. Стандартизировать share-ссылки на новые пути.
17. Добавить smoke-тесты на ключевые redirect-маршруты.
18. Обновить docs, чтобы новый формат не "расползался" в PR.
19. Локально подсвечивать неканонические пути в dev-логах (опционально).
20. Постепенно заменить хардкоды строк путей на helper-функции.
