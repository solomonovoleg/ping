# Сид `seed:social-content` — почему не видно постов и сториз

## Позитивный / познавательный контент в постах

В `seed-social-content.ts` массив **`POSITIVE_EDU_FUN_POST_TEXTS`** (~24 текста) **всегда** добавляется в общий пул текстов и перемешивается с RSS и fallback — в ленте сидов появляется больше лёгкого, вдохновляющего и «фактического» контента. Чтобы обновить прод: снова **`npm run deploy:seed-social`** или **`seed:social-fresh`**.

## Картинки в постах и аватарах

Сид использует **images.unsplash.com** для постов, обложек и аватаров. Раньше использовались picsum/pravatar — из части сетей (в т.ч. РФ) они не открываются, в ленте выглядит как «без фото». После смены URL нужен повторный **`npm run seed:social-fresh`** или **`deploy:seed-social`** (`--reset` пересоздаёт посты с новыми ссылками).

## Сториз

1. **Срок жизни**  
   В API отдаются только сториз с `expires_at > now()`. Раньше сид выставлял **24 часа** с момента «времени создания» сториз — через день лента сториз с сидов пустая.  
   Сейчас по умолчанию **7 дней** (`SEED_STORY_TTL_HOURS`, по умолчанию `168`). Для короткого TTL: `SEED_STORY_TTL_HOURS=24 npm run seed:social-content`.

2. **Сид не запускался на этой БД**  
   Нужен один успешный прогон на сервере с рабочим `DATABASE_URL` и загруженными RSS (или флаг `--allow-fallback`).

3. **Сиды уже есть, скрипт сразу выходит**  
   Если в БД уже есть пользователи `seed_social_*`, скрипт **ничего не добавляет**, пока не запустить с **`--reset`** (удалит старых сидов и создаст заново).

## Посты

1. **Лента = не все посты в базе**  
   Перед ранжированием сервер берёт только **последние N постов** по дате (`FEED_RANKING_CANDIDATE_MAX`, по умолчанию **800**). Если на проде тысячи «свежих» постов от реальных пользователей, **старые посты сидов могут вообще не попасть в выборку** — их не «удалило», они просто не в топ-800 по `created_at`.

2. **Что сделать**  
   - Увеличить лимит на сервере, например: `FEED_RANKING_CANDIDATE_MAX=2500` в `.env`.  
   - Или временно включить хронологию: `FEED_ALGO_MODE=strict_chrono` (всё равно в пределах того же пула кандидатов — при очень большой ленте лучше поднять `FEED_RANKING_CANDIDATE_MAX`).  
   - Пересоздать сид с **новыми датами** постов: `npm run seed:social-content -- --reset` (осторожно: удаляет старых `seed_social_*`).

## Подписки

Лента постов **не фильтрует только подписок** — видны **все публичные** посты (кроме блокировок).  
Сториз в ленте: **свои**, **подписки**, и публичные профили (`profile_visibility = all`). Сиды по умолчанию публичные.

## Клиент: полоска сториз

Если API вернул **пустой** массив сториз, в UI могут показываться **демо-кружки** (Алиса, Мама и т.д.) — это **не** сид-пользователи. Реальные сиды приходят только из `GET /api/stories/feed`.

## Команды

```bash
# На проде с локальной машины (нужен deploy.env с VPS_*): то же на сервере в $VPS_PATH
npm run deploy:seed-social

# Локально / на сервере вручную в каталоге приложения:
# Рекомендуется: за один раз удалить старых сидов, создать тестовых пользователей, посты и сториз (RSS не обязателен — есть fallback-тексты)
npm run seed:social-fresh

# То же вручную:
npm run seed:social-content -- --reset --allow-fallback

# Уже есть seed_social_*, но постов нет (например сид упал после создания юзеров):
npm run seed:social-content -- --fill-content --allow-fallback

# только подписать «Леху» и +79956012736 на уже существующих seed_social_* (после миграции designated follows часто не нужно)
npm run seed:auto-follow
```

После `--reset` / `seed:social-fresh` на проде снова выполните деплой/миграции или `node scripts/migrate-designated-follows.cjs`, чтобы подписки на сидов вернулись в `follows`.
