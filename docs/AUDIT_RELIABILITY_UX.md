# Аудит надёжности и UX (экспертная оценка)

Почему приложение может вызывать ощущение «всё криво работает» и что с этим делать.

---

## 1. Сеть и повторные попытки

**Проблема:** В `queryClient` стоит `retry: false` — при любой ошибке сети (включая кратковременный обрыв) запрос сразу считается провалившимся, пользователь видит «Не удалось загрузить» без единой повторной попытки.

**Восприятие:** «Один раз не загрузилось — приложение сломано».

**Рекомендация:** Включить 1–2 повтора с задержкой для запросов (уже внедрено в коде).

---

## 2. Истечение сессии (401)

**Проблема:** При 401 (токен/сессия истекли) пользователь может продолжать видеть старые данные или получать ошибки запросов без явного сообщения «сессия истекла».

**Восприятие:** «Сделал действие — ничего не произошло» или «ошибка без объяснения».

**Рекомендация:** При первом 401 после авторизации показывать тост «Сессия истекла. Войдите снова» и сбрасывать авторизацию (уже внедрено).

---

## 3. Тихие провалы (.catch(() => {}))

**Проблема:** Много вызовов с пустым `catch` или `.catch(() => {})`: отметка прочтения, регистрация push-токена, часть звонков. Пользователь не видит, что что-то не выполнилось.

**Восприятие:** «Иногда что-то не работает, но непонятно что».

**Рекомендация:** Для некритичных действий (прочтение, пуш) тихий fail допустим. Для критичных — показывать тост или inline-ошибку. По возможности логировать в консоль в dev.

---

## 4. Нет глобального Error Boundary

**Проблема:** Необработанная ошибка в любом компоненте роняет всё дерево React — пользователь видит пустой экран без пояснения.

**Восприятие:** «Приложение вылетело».

**Рекомендация:** Обернуть приложение в Error Boundary с запасным UI («Что-то пошло не так» + кнопка обновить) (внедрено).

---

## 5. Состояния загрузки и ошибок

**Что уже хорошо:**
- Спиннер при загрузке авторизации.
- Скелетоны в списке чатов и постов.
- Кнопки «Повторить» при ошибке загрузки чатов и ленты.
- Тосты при ошибках отправки сообщений и постов.

**Что можно усилить:**
- Единый вид «загрузка» (скелетон или спиннер) на ключевых экранах.
- Явная блокировка кнопки «Отправить» с индикатором при отправке (частично есть).
- При ошибке мутации (отправка, удаление) всегда тост с коротким текстом и, где уместно, «Повторить».

---

## 6. Оптимистичные обновления

**Что уже хорошо:** Сообщение в чате добавляется сразу при отправке, затем приходит ответ сервера.

**Риск:** При ошибке ответа сообщение уже «висит» в списке; нужно откатывать и показывать ошибку (в текущей реализации при ошибке сообщение не добавляется, тост показывается — ок).

---

## 7. Real-time и консистентность

**Исправлено ранее:**
- Список чатов обновляется при новом сообщении (в т.ч. у отправителя).
- В превью чатов отображаются «печатает…» и «записывает голосовое».

**Проверить:** Стабильность WebSocket при долгой работе в фоне (переподключение при разрыве — по необходимости).

---

## 8. Нативное приложение (iOS/Capacitor)

**Уже учтено:**
- Bearer-токен и сохранение в localStorage для сессии после перезапуска.
- Safe area для шапки и контента.
- Разрешения камеры/микрофона/галереи в Info.plist.

**Рекомендация:** При первом 401 в нативном приложении показывать тот же тост «Сессия истекла», не полагаться только на редирект.

---

## Итоговые приоритеты

| Приоритет | Действие | Статус |
|-----------|----------|--------|
| Высокий   | Включить retry для запросов | ✅ |
| Высокий   | Тост «Сессия истекла» при 401 | ✅ |
| Высокий   | Error Boundary на всё приложение | ✅ |
| Средний   | Единообразные скелетоны/спиннеры на основных экранах | по желанию |
| Низкий    | Логирование тихих ошибок в dev | по желанию |

После внедрения отмеченных пунктов приложение должно ощущаться стабильнее и предсказуемее для пользователя.
