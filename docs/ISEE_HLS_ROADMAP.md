# iSee: дорожная карта HLS (опционально)

Цель — **адаптивный битрейт** и меньше ожидания на слабой сети. Объём работ сопоставим с отдельным подпроектом; здесь зафиксированы ориентиры без обязательства сроков.

## Пайплайн (сервер / воркер)

1. После загрузки постового MP4 (или отдельный воркер по очереди): **транскод** в HLS — `master.m3u8` + сегменты (`.ts` или fMP4), выкладка в S3 рядом с объектом или в префикс `posts/<id>/`.
2. В БД или в ответе API ленты: поле вроде **`hlsUrl`** (публичный или presign по текущим правилам).
3. **CDN / кеш**: короткий TTL для плейлиста, длиннее для сегментов; **CORS** для домена веб-клиента.

## Клиент

1. **Safari / iOS**: нативный HLS в `<video src="…m3u8">` при поддержке.
2. **Chrome / Firefox / десктоп**: **hls.js** с `HTMLMediaElement`, общая обвязка с текущим `FeedInlineVideo` / пулом рилсов.
3. **Fallback**: если HLS нет (старые посты) — текущий **MP4** URL.

## Совместимость

- Согласовать с **presigned URL** и сроком жизни подписи vs длительность сессии просмотра.
- Не ломать **постер** (JPEG) и метрику **time-to-first-play**; при переключении на HLS уточнить момент «первого playing».
