# Чеклист деплоя PING MOOT

Проверка перед деплоем в **отдельную папку** с **отдельным доменом**, чтобы не затронуть другие проекты на сервере.

---

## 1. Архитектура деплоя

| Что | Как сделано |
|-----|-------------|
| **Папка на сервере** | Отдельная: `VPS_PATH=/var/www/ping-moot` (задаётся в `deploy.env`). Другие проекты лежат в своих папках. |
| **Порт** | Строго **3080**. Не пересекается с другими приложениями. |
| **Домен** | Привязывается в nginx только к этому приложению: `server_name pingos.ru` в `deploy/nginx-ping-moot.conf`. Остальные домены обрабатываются своими конфигами. |
| **БД** | Отдельная БД и пользователь PostgreSQL: `ping_moot` / пользователь `ping_moot`. |

Итог: деплой в свою папку и свой домен **не затрагивает** другие проекты.

---

## 2. База данных и миграции

### 2.1 Подключение

- Приложение читает **`DATABASE_URL`** из `.env` на сервере (через `dotenv/config` при старте).
- Формат: `postgresql://ping_moot:ПАРОЛЬ@localhost:5432/ping_moot`.
- При деплое через `npm run deploy`: если в **deploy.env** задан DATABASE_URL, скрипт **записывает** .env на сервере из deploy.env (править на сервере не нужно). При использовании `deploy/upload.sh` .env создают или правят вручную на сервере.

### 2.2 Схема и миграции

- **Схема Drizzle:** таблицы описаны в `shared/schema/*.ts` (users, chats, messages, referrals, admin и т.д.).
- **Команда обновления схемы:** `drizzle-kit push` (синхронизирует схему с БД без миграционных файлов).
- Конфиг: `drizzle.config.ts`, путь к схеме: `./shared/schema/*.ts`.

### 2.3 Где и как запускать миграции

**Вариант A — локально против серверной БД**

1. В корне проекта создай `.env` с `DATABASE_URL`, указывающим на серверную БД (через SSH-туннель или разрешённый удалённый доступ).
2. Выполни:
   ```bash
   npm run db:push
   ```
   Или:
   ```bash
   npx drizzle-kit push --config=drizzle.config.ts
   ```

**Вариант B — на сервере**

1. На сервере в папке приложения должен быть `.env` с верным `DATABASE_URL`.
2. Запуск (если установлен `drizzle-kit`):
   ```bash
   cd /var/www/ping-moot && . ./.env && npx drizzle-kit push --config=drizzle.config.ts
   ```
3. При деплое скрипт `deploy/upload.sh` уже вызывает миграции через `npx drizzle-kit@latest push`. Если команда падает (нет модуля и т.п.), в логе будет предупреждение — тогда миграции нужно выполнить вручную одним из способов выше.

**Если на сервере не хватает колонок** (например, после обновления схемы):

- Есть запасной скрипт: `scripts/migrate-users-columns.cjs` (добавляет недостающие колонки в `users`).
- Запуск на сервере:
  ```bash
  cd /var/www/ping-moot && ( set -a; [ -f .env ] && . ./.env; set +a; node scripts/migrate-users-columns.cjs )
  ```

### 2.4 Проверка, что БД работает

- Успешный вход/регистрация в приложении.
- Отсутствие ошибок вида `password authentication failed for user "ping_moot"` или `column "..." does not exist` (если такие были — поправить `.env` и/или выполнить миграции/скрипт выше).

## 3. Деплой (отдельная папка, домен, порт 3080)

### 3.1 Перед деплоем

- [ ] В корне проекта настроен `deploy.env`: `VPS_HOST`, `VPS_USER`, `VPS_PASSWORD`, **`DATABASE_URL`** (или `DB_PASSWORD`), при необходимости `VPS_PATH=/var/www/ping-moot`.
- [ ] В PostgreSQL созданы пользователь и БД: `CREATE USER ping_moot WITH PASSWORD '...'; CREATE DATABASE ping_moot OWNER ping_moot;`
- [ ] При первом деплое скрипт создаст на сервере `.env` из `deploy.env` и запустит миграции. Подробнее: `docs/DEPLOY_RULES.md`.

### 3.2 Команда деплоя (рекомендуется)

Из **корня проекта**:

```bash
npm run deploy
```

Скрипт `scripts/deploy.sh`:

1. Собирает проект (`npm run build`).
2. Заливает файлы на сервер (rsync в `VPS_PATH`).
3. Если в `deploy.env` задан **DATABASE_URL**, перезаписывает `.env` на сервере из `deploy.env` (источник истины — один файл, см. `docs/DEPLOY_RULES.md`).
4. На сервере выполняет `scripts/server-setup.sh`: зависимости, миграции (`run-migrations.cjs`), PM2.

**Альтернатива** (без записи .env из deploy.env, .env на сервере создаётся вручную):

```bash
source deploy.env && ./deploy/upload.sh
```

### 3.3 После деплоя на сервере

- Приложение должно запускаться из **этой же папки** (`VPS_PATH`), иначе путь к `dist/` и к `.env` будет неверный.
- Рекомендуется один процесс PM2 для этого приложения (сессии в памяти — `memorystore`), например: `pm2 start ecosystem.config.cjs` из `VPS_PATH`.
- В панели хостинга/фаервола должен быть открыт порт **3080** для доступа снаружи (если заходите по IP:3080).

### 3.4 Домен и HTTPS (чтобы открывался именно этот проект, а не другой)

- Конфиг nginx только для этого приложения: `deploy/nginx-ping-moot.conf`.
- В нём указан **свой** домен: `server_name pingos.ru www.pingos.ru;` и проксирование на `127.0.0.1:3080`.

**Почему по https:// открывался другой проект:** nginx обрабатывает HTTPS (порт 443) тем server-блоком, у которого есть `listen 443 ssl` и подходящий `server_name`. Если у этого проекта не было блока для 443, запросы шли в default или в конфиг другого сайта. В конфиг добавлен отдельный блок для **443** с `server_name pingos.ru www.pingos.ru` — теперь именно этот проект отвечает на https://pingos.ru.

**Что сделать на сервере:**

1. Получить SSL-сертификат (один раз):  
   `sudo certbot certonly --nginx -d pingos.ru -d www.pingos.ru`  
   (или через `--webroot`, если nginx не должен временно держать 80).
2. Скопировать конфиг:  
   `cp deploy/nginx-ping-moot.conf /etc/nginx/sites-available/pingos.ru`  
   Симлинк:  
   `ln -sf /etc/nginx/sites-available/pingos.ru /etc/nginx/sites-enabled/`
3. Проверка и перезагрузка:  
   `nginx -t && systemctl reload nginx`

Если сертификата ещё нет, временно закомментируй на сервере весь блок `server { listen 443 ssl; ... }` в этом конфиге, затем после получения сертификата раскомментируй и снова `nginx -t && systemctl reload nginx`. Другие сайты не трогать.

## 4. Краткая проверка «всё ли ок»

| Проверка | Как |
|----------|-----|
| БД | Вход/регистрация работают, нет ошибок про `ping_moot` или отсутствующие колонки. |
| Миграции | После изменения схемы выполнен `drizzle-kit push` (локально или на сервере). |
| Деплой в свою папку | В `deploy.env` указан свой `VPS_PATH`; на сервере приложение запущено из этой папки. |
| Свой домен | В nginx только свой `server_name`, проксирование на 3080; другие проекты не затронуты. |
| Порт 3080 | Открыт в фаерволе; приложение слушает `0.0.0.0:3080`. |

---

## 5. Про платформы вроде Vercel / Netlify

Текущая сборка — **один Node-сервер** (Express + SPA из `dist/public`), который сам отдаёт API и статику. Такой вариант рассчитан на **VPS/собственный сервер** (отдельная папка, свой домен, порт 3080).

Для **Vercel/Netlify** обычно нужны отдельный backend (serverless/Node) и отдельный фронт; перенос потребует изменений архитектуры и не входит в этот чеклист.

Если под «errpfyye» имелась в виду **другая платформа** — напиши название, можно будет отдельно расписать шаги под неё.

## 6. Итог проверки проекта

- **Деплой в отдельную папку и свой домен:** да, через `VPS_PATH` и отдельный конфиг nginx; другие проекты не затрагиваются.
- **БД:** используется одна БД `ping_moot` и пользователь `ping_moot`; подключение через `DATABASE_URL` из `.env`.
- **Миграции:** `drizzle-kit push` и путь к схеме `./shared/schema/*.ts` проверены; при деплое миграции вызываются из `upload.sh`, при ошибке — выполнить вручную (локально или на сервере).
- **Сессии:** в памяти (MemoryStore), нужен один процесс PM2; для нескольких инстансов понадобится Redis или `connect-pg-simple`.
